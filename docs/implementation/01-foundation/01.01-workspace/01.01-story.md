# Story 01.01: Workspace architecture

As a developer, I need explicit crate boundaries so rules, presentation, protocol, and hosting can evolve independently.

## Tasks

- [01.01.01 Create workspace crates](01.01.01-create-workspace.md)
- [01.01.02 Pin toolchain and dependencies](01.01.02-pin-toolchain.md)

## Dependencies

- None.

## Acceptance criteria

- Workspace members compile independently and together.
- `crownline_core` contains no Bevy, network, filesystem, or clock dependency.
- Client and server can both depend on core and protocol without circular dependencies.

## Cross-cutting concerns

- Determinism, portability, compile time, and dependency hygiene.
