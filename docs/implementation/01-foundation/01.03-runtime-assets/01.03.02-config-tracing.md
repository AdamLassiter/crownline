# Task 01.03.02: Establish configuration and tracing

Define client settings storage, server environment configuration, structured tracing, and player-safe error boundaries.

## Status

- [x] Done

## Implementation notes

- Client settings load from the platform configuration directory, tolerate absence, validate individual fields, and fall back with a warning.
- Server bind/log-format environment variables have actionable validation; tracing supports human and JSON formats plus `RUST_LOG` filtering.
- Current logs contain no credentials, and the logging boundary is structured so future reconnect tokens can be redacted before emission.

## Acceptance criteria

- Invalid configuration identifies the field and accepted form.
- Server logs can be emitted as human-readable or JSON records.
- Secrets and reconnect tokens are redacted.
- Client settings use platform-appropriate user-data locations and tolerate a missing file.

## Cross-cutting concerns

- Privacy, security, recoverability, and operator usability.
