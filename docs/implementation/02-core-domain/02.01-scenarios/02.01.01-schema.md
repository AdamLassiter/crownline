# Task 02.01.01: Define scenario schema

Define board dimensions, tile terrain, edge barriers, sites, Keeps, deployments, Pawn directions, castling routes, rule toggles, timing values, and display metadata.

## Status

- [x] Done

## Implementation notes

- Added versioned Serde/RON domain types for boards, coordinates, pieces, terrain, canonical shared edges, sites, fortifications, castling routes, rule toggles, timing, and metadata.
- IDs and collections use stable ordered representations; presentation-only colors are excluded.
- Unsupported schema versions are explicitly represented by validation errors.
- [Bug 001](../../bugs/001-scenario-rules-excessive-bools-lint.md) replaced the custom-army Boolean with an explicit `ArmySetup` enum after strict Clippy verification exposed the schema smell.
- [Bug 002](../../bugs/002-missing-keep-schema.md) added the omitted Keep ownership, tile, gate, and fortification-link schema required by the task description and GDD.
- [Bug 004](../../bugs/004-missing-default-scenario-metadata.md) added a backward-compatible machine-readable default marker required by authored scenario discovery.

## Dependencies

- 01.01.01.

## Acceptance criteria

- Schema represents open/forest/mountain/road tiles and river/bridge/ford/wall/gate edges.
- Settlements, promotion sites, and fortifications have stable IDs.
- Double-step, en passant, designated castling, development, production, and promotion timing are configurable.
- Unknown future schema versions are rejected explicitly.

## Cross-cutting concerns

- Avoid encoding presentation-only colors into canonical rule state.
