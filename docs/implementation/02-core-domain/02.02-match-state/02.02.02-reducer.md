# Task 02.02.02: Define actions and transitions

Define Move, Hold, promotion choice, Pawn-placement choice, resignation, draw, and match-control actions plus typed transition results.

## Status

- [x] Done

## Implementation notes

- `apply_action` is the deterministic reducer entry point for Move, Hold, promotion, Pawn placement, resignation, and draw actions.
- Successful actions return canonical state plus serializable transition events for movement, capture, castling, promotion, production, turn changes, draw control, and match end.
- Promotion assigns a new stable piece identity and reports the old-to-new mapping; settlement production also allocates from the canonical identity counter.
- Mandatory choices are ordered and block Move/Hold until the queue is resolved. Typed failures distinguish actor, phase, queued choice, target, settlement state, and terminal matches.
- Start-of-turn discovery and ordering of realm choices remains deliberately owned by Task 04.03.02; this task supplies their reducer contract.
- Verified with focused reducer tests, the core Clippy gate, and the full workspace check.

## Acceptance criteria

- Applying an invalid action leaves state unchanged.
- Successful transitions report state changes needed by UI, journal, and network layers.
- Mandatory choices prevent Move/Hold until resolved.
- Errors distinguish stale phase, wrong player, illegal target, and terminal match.

## Cross-cutting concerns

- No reducer path reads system time or performs I/O.
