# Task 02.03.01: Define save and snapshot envelopes

Create versioned JSON envelopes for local saves and authoritative snapshots, with explicit scenario and application versions.

## Dependencies

- 02.02.01.

## Status

- [x] Done

## Implementation notes

- Added bounded JSON `SaveEnvelope` and `SnapshotEnvelope` formats carrying explicit format, application, and scenario-schema versions plus scenario identity, canonical state, and its integrity hash.
- Readers return typed recoverable errors for malformed/truncated JSON, excessive payloads, unsupported versions, metadata mismatches, invalid state, integrity failure, and snapshot revision mismatch.
- `SaveReader` selects migrations only from an explicit declared-source-version registry; there is no structural version inference.
- `AtomicSaveStorage` keeps filesystem policy in the host while enforcing write-temporary, read-back, validate, then atomic-replace ordering. Failed validation discards the temporary payload and never requests replacement of the prior save.
- Round-trip coverage includes both command and pending-choice phases, both mandatory choice variants, clocks, draw state, terminal state, and canonical integrity metadata.
- Actual platform filesystem/path integration remains in Task 07.03.03.

## Acceptance criteria

- Round-trip tests cover every state variant and pending phase.
- Corrupt, truncated, and unsupported saves return recoverable errors.
- Migrations are registered by source version rather than inferred.
- Local-save APIs support write-to-temporary then atomic replacement.

## Cross-cutting concerns

- Do not overwrite the last valid save until replacement validation succeeds.
