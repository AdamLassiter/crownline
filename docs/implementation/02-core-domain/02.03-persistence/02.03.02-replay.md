# Task 02.03.02: Define action journals and replay

Record accepted actions with actor, revision, idempotency key, and deterministic transition metadata.

## Dependencies

- 02.02.02, 02.03.01.

## Status

- [x] Done

## Implementation notes

- Added a bounded, versioned `ActionJournal` with explicit application/scenario versions and an initial-state integrity hash.
- Each accepted record stores the actor, before/after revisions, fixed-size opaque idempotency key, canonical action, deterministic domain transition events, and resulting state hash.
- Append verifies that the supplied state matches the journal tail. Reused idempotency keys return the original accepted revision/hash without applying or recording another action.
- Replay reconstructs from the validated scenario, never reapplies duplicate keys, and verifies actor, revisions, events, and hash at every record.
- Divergence errors identify the first affected revision and include recorded versus reconstructed hashes.
- The journal schema has no credential or presentation-event fields; fixed-size keys and record/JSON limits bound audit data.

## Acceptance criteria

- Replaying from the same initial scenario yields the recorded final hash.
- Duplicate idempotency keys do not apply twice.
- Replay reports the first divergent revision and expected/actual hash.
- Journals omit credentials and presentation-only events.

## Cross-cutting concerns

- Auditability, bounded record size, and forward compatibility.
