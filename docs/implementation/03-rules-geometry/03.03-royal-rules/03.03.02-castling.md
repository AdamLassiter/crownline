# Task 03.03.02: Implement designated castling

Use scenario-defined King/Rook starts, King traversal, and final squares rather than assuming an eight-file board.

## Dependencies

- 03.03.01.

## Acceptance criteria

- Castling requires both pieces unmoved, a clear legal route, no current check, and no attacked King traversal/destination.
- Terrain and edge barriers apply to the configured route.
- Moving or losing either participant permanently removes that route's right.
- One action moves both pieces atomically and journals one command.

## Cross-cutting concerns

- The UI receives the complete two-piece preview from the transition.
