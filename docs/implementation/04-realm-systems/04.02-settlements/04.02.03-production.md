# Task 04.02.03: Implement Pawn production

Advance established settlements through production and queue an adjacent-square placement choice when ready.

## Status

## Implementation notes

- Established settlements without a living supported Pawn advance bounded production once per continuously valid owner cycle using the validated scenario threshold and interruption policy.
- Reaching readiness queues an ordered mandatory `PlacePawn` choice without consuming the player's Command. Public placement queries return all empty, board-bounded, Mountain-free, edge-passable King-adjacent squares.
- If every destination is blocked, progress remains at the ready threshold; a later owner boundary queues placement as soon as a legal square opens.
- Placement allocates a stable identity, records settlement origin, resets production progress, and emits production/readiness/Pawn events. Settlement-origin Pawns cannot double-step.
- A living produced Pawn occupies capacity and prevents further progress. Capture or promotion clears the stable reference and reopens capacity for a later cycle.
- Focused tests cover readiness and placement, mandatory phase behavior, blocked readiness persistence, Mountain/wall/river filtering, capacity, promotion release, and double-step exclusion.
- [Bug 003](../../bugs/003-repetition-recorded-before-realm-effects.md) ensures the repetition entry includes the queued mandatory choice rather than the transient pre-realm state.

## Acceptance criteria

- Production obeys the same continuous requirements and pause rule as establishment.
- Legal destinations are all unoccupied, passable king-adjacent squares.
- With no legal destination, readiness persists without losing progress.
- Capacity remains occupied until the linked Pawn is captured or promotes; produced Pawns lack double-step rights.

## Cross-cutting concerns

- Placement is a mandatory choice, not the turn's Command.
