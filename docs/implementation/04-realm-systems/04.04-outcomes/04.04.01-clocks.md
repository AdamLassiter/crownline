# Task 04.04.01: Implement optional chess clocks

Model remaining time and increments with a clock-service boundary usable by local and server hosts.

## Dependencies

- 04.03.03.

## Acceptance criteria

- Clock starts when a match starts and runs during mandatory choices and the command phase.
- Accepted Move/Hold stops the actor's clock, adds increment, and starts the opponent's clock.
- Online deadlines continue through disconnect and server downtime; local clocks pause while the application is closed.
- Expiration is applied exactly once and beats later commands.

## Cross-cutting concerns

- Use monotonic time while running and persist wall-clock deadlines only at the hosting boundary.
