Model remaining time and increments with a clock-service boundary usable by local and server hosts.

## Implementation notes

- `ClockSettings` preserves untimed play as the default and validates the documented 1-180 minute base and 0-60 second increment bounds before a match starts.
- The core clock service accepts elapsed milliseconds explicitly and charges the active player in both mandatory-choice and command phases; it has no wall-clock or Bevy dependency.
- `apply_timed_action` advances time before rule validation, makes expiration win at the exact deadline, and applies increment only after an accepted Move or Hold starts the opponent turn.
- Timeout is a single revisioned terminal transition with a typed clock update and match-ended event. Subsequent clock advances and actions are rejected as already finished.
- Timed journals store initial clock values and per-action elapsed input, so clocked transitions serialize and replay deterministically.
- Local monotonic sampling and closed-application pause behavior are host responsibilities in Task 07.03.02. Persisted wall-clock deadlines and downtime charging are server responsibilities in Task 08.03.02; both feed this same explicit elapsed-time boundary.

## Acceptance criteria

- Clock starts when a match starts and runs during mandatory choices and the command phase.
- Accepted Move/Hold stops the actor's clock, adds increment, and starts the opponent's clock.
- Online deadlines continue through disconnect and server downtime; local clocks pause while the application is closed.
- Expiration is applied exactly once and beats later commands.

## Cross-cutting concerns

- Use monotonic time while running and persist wall-clock deadlines only at the hosting boundary.
