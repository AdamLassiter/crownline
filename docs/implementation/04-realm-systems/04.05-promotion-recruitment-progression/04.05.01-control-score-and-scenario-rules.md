# Task 04.05.01: Define control score and scenario rules

Add a deterministic realm-control calculation and scenario-authored promotion unlock thresholds.

## Status

- [x] Done

## Implementation notes

- Scenario schema v2 adds `PromotionUnlockRules`; schema v1 remains accepted and omitted rules deserialize to the 2/4/8 default. All shipped scenarios explicitly author the default ladder.
- `RealmControlScore` exposes owned, governed, and established settlement counts with the canonical weighted total. It validates scenario/state alignment and uses the existing governance resolver rather than duplicating line rules.
- Scenario and golden-replay version fixtures plus archived opening-probe scenario hashes were deliberately refreshed; action/state traces did not change because this task defines configuration and scoring without enforcing promotion restrictions yet.
- Focused unlock/default/score tests and the full repository check passed on 2026-07-27.

## Dependencies

## Scope

- Add a typed promotion-unlock rule to `ScenarioRules` with Bishop, Rook, and Queen score thresholds; Knight has no threshold because it is always available.
- Default an omitted rule to Bishop 2, Rook 4, and Queen 8, including legacy and custom scenario definitions.
- Author the 2/4/8 rule explicitly in Introductory, Standard, and Large scenario data.
- Calculate a player's score from settlements they currently own: 1 ownership point, 1 additional point for live governance, and 2 additional points for establishment per settlement.
- Expose a typed breakdown containing owned, governed, established, and total contributions so rules, UI, diagnostics, and later AI evaluation share one calculation.
- Validate that thresholds are nondecreasing and representable, and update scenario schema versions, canonical hashes, examples, and fixtures deliberately.

## Acceptance criteria

- Identical scenario and match state produces an identical score and breakdown regardless of collection iteration order.
- An unowned settlement contributes nothing, even if a piece currently attacks or could govern it.
- Governance contributes only when the canonical governance report identifies the owner as the current governor; establishment contributes only while the established settlement is owned by that player.
- Threshold validation accepts 2/4/8 and rejects descending or otherwise invalid ladders with actionable errors.
- Scenario definitions without the new field load with 2/4/8, while all three shipped scenarios carry the values explicitly.
- Scenario serialization, canonical hashing, and schema tests cover both explicit and omitted rules.

## Cross-cutting concerns

- Deterministic coordinate ordering, checked arithmetic, schema compatibility, actionable validation, and a single reusable score implementation.
