# Task 04.05.03: Preserve eligibility through persistence and networking

Carry frozen promotion eligibility through every save, replay, protocol, and authoritative-server boundary.

## Status

- [x] Done

## Implementation notes

- Core save, authoritative snapshot, replay journal, local-save wrapper, scenario schema, and client/server protocol versions advanced to 2. Scenario-aware readers support format/schema 1 and retain typed rejection for future versions.
- Legacy saves paused at promotion deserialize missing eligibility safely, then calculate realm control once and clone one validated snapshot across the entire queued batch. Local wrapper migration also normalizes its embedded scenario and canonical hash without rewriting the source file.
- Current reads validate eligibility against the stored control breakdown, configured unlock ladder, and every peer in the batch. Malformed or mixed snapshots fail before any reducer mutation.
- Format 1 journals migrate by replaying their actions under current rules and regenerating deterministic events and hashes. A historical action that is no longer legal returns an actionable migration failure rather than a partial journal.
- Full network snapshots carry the canonical promotion data. Tests cover non-default protocol encode/decode, stable snapshot validation, SQLite authority restart at a genuine pending promotion, format-1 multi-choice migration, legacy implicit 2/4/8 rules, and local-wrapper migration.
- Golden replay headers were deliberately updated to journal/schema format 2; only the combined-realm canonical hashes from promotion readiness onward changed. The compatibility policy records the supported paths and protocol-1 incompatibility.

## Scope

- Serialize the frozen score, breakdown, and allowed kinds in match state, save data, journals, replay fixtures, and authoritative network snapshots.
- Version and migrate persisted formats where required, retaining actionable rejection for unsupported future versions.
- When an older save is paused at promotion, calculate one score from its restored canonical state and assign that same snapshot to every choice already in the promotion queue.
- Preserve the snapshot across server recovery and client reconnect instead of deriving it from a possibly later presentation state.
- Map a locked-kind transition failure to a stable public action rejection without leaking unrelated canonical or hidden state.
- Update canonical-hash and golden-replay fixtures intentionally, including documentation of why their identities changed.

## Acceptance criteria

- Save/load, journal replay, network encode/decode, server recovery, and reconnect round trips preserve exactly the same frozen eligibility.
- Legacy scenario data uses the implicit 2/4/8 ladder.
- A legacy save with multiple pending promotions migrates all choices with one shared batch snapshot.
- A reconnected client cannot observe or submit promotion options different from the authoritative state.
- Golden replay and canonical-hash changes are reproducible and reviewed rather than silently regenerated.
- Malformed eligibility data, unsupported versions, and illegal network actions fail without partial state mutation or process panic.

## Cross-cutting concerns

- Backward compatibility, bounded decoding, canonical identity, replay determinism, reconnect safety, fog-safe public errors, and explicit migration evidence.
