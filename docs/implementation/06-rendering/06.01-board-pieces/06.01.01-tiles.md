# Task 06.01.01: Render tiles and terrain

Render checkerboard squares with composited tints for open, forest, mountain, and road terrain.

## Dependencies

- 02.01.01.

## Status

- [x] Done

## Implementation notes

- Added a Bevy board-rendering plugin that projects the bundled default scenario into one code-native square Sprite per canonical coordinate, centered around the world origin.
- Checker parity is derived only from `x + y`; world orientation and later camera changes cannot alter it.
- A reusable `BoardPalette` resource maps the two parities across open, forest, mountain, and road treatments. Tiles use Sprite colors directly, avoiding per-tile material asset allocations.
- Light/dark contrast is preserved for every terrain, while all four treatments maintain separated relative luminance within each parity so they remain distinguishable without hue alone.
- Missing terrain presentation metadata falls back to the open treatment. Authored scenarios remain limited to the closed canonical terrain enum.
- Every square uses the same exact size, grid-step translation, and coplanar tile depth. A headless ECS fixture verifies all 400 default-board tiles have gapless alignment and no tile-layer z separation.

## Acceptance criteria

- Board parity is stable by coordinate and unaffected by camera orientation.
- Forest, mountain, and road remain distinct in color-vision simulations.
- Terrain layers align without gaps or z-fighting at all zoom levels.
- Unknown presentation metadata falls back safely.

## Cross-cutting concerns

- Use reusable materials/components rather than one material allocation per tile.
