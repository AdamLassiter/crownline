# Task 06.01.02: Render Unicode pieces

Render U+2654-U+2659 silhouettes with the bundled font and player-specific text colors.

## Dependencies

- 01.03.01, 06.01.01.

## Status

- [x] Done

## Implementation notes

- The rendering plugin constructs canonical state for the displayed scenario and maps King through Pawn to the single unfilled Unicode silhouette range U+2654-U+2659 for both players.
- All glyphs use the bundled Noto Sans Symbols 2 handle, one centered 26px text treatment, and a shared piece layer above tiles.
- Ownership uses player-specific text colors plus a high-contrast code-native backplate: North receives a dark square and South a light diamond. Silhouette fill is never used as the ownership signal.
- `PieceVisual` keys each parent entity by canonical `PieceId`. The sync system moves an existing entity when that ID's coordinate changes, retires missing IDs, and spawns replacement IDs for promotion without rebuilding unrelated pieces.
- Font load/corruption failure hides every tagged glyph and shows the existing visible ASCII diagnostic. The monitor continues enforcing fallback visibility so pieces created after a failure cannot reappear with missing glyph boxes.
- Headless fixtures cover the exact glyph mapping, 32 unique initial IDs, stable-entity movement, and promotion replacement of only the retired identity.

## Acceptance criteria

- All types are centered, consistently sized, and legible on every terrain tint.
- Player identity also has an optional outline/backplate cue.
- Piece entities update by stable piece ID across movement and promotion.
- Missing glyph detection produces a visible diagnostic fallback.

## Cross-cutting concerns

- Do not rely on Unicode white/black glyph fill to encode ownership.
