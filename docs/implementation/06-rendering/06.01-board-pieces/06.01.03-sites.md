# Task 06.01.03: Render sites and ownership

Draw settlements, promotion sites, Keep tiles, fortifications, rivers, bridges, fords, walls, and gates using code-native shapes and labels.

## Status

## Implementation notes

- Added a dedicated code-native feature layer for Keep tiles, settlement rings, promotion crosses, fortification labels, and every canonical edge kind.
- Edge transforms use the exact midpoint of their two canonical tile centers. Horizontal and vertical Sprite dimensions follow edge orientation, so rivers, bridges, fords, walls, and gates share the same authored boundary without drift.
- Bridges, fords, and gates combine distinct thickness/color treatments with `=`, dotted, and slash labels; walls and rivers retain unique neutral and blue bars.
- Settlement marks use a ring larger than the piece backplate, leaving their type visible under an occupant. Ownership rebuilds the mark with both player color and an `N`/`S` emblem plus square/diamond ring orientation; neutral sites use a separate dot cue.
- Promotion sites use a purple diagonal cross, Keeps use a low-alpha owner tint, and fortification towers use a compact `T` label. Roads remain only a base-tile terrain tint and never add the elevated outline/mark used by rule overlays.
- Layer order is explicit and tested: tile, Keep tint, site, edge/barrier, piece backplate, then glyph. Headless fixtures verify default feature counts, dynamic settlement ownership, canonical edge alignment, and site span around pieces.

## Acceptance criteria

- Edge barriers align with their canonical shared edges.
- Site type remains recognizable under a piece.
- Settlement ownership has both color and emblem/ring cues.
- Roads never resemble a legal-move highlight.

## Cross-cutting concerns

- Visual layering order is documented and tested with composite tiles.
