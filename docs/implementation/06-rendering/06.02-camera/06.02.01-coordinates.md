# Task 06.02.01: Implement coordinate conversion and picking

Create tested functions converting canonical coordinates to world positions and cursor rays back to optional board squares.

## Status

- [x] Done

## Implementation notes

- Added `BoardGeometry` as the sole canonical board/world conversion boundary, parameterized by board dimensions, tile size, and an explicit North-at-top or South-at-top orientation.
- Coordinate centers round-trip in both orientations. Picking uses half-open board bounds, rejects non-finite values and invalid tile sizes, handles negative world positions, and returns `None` for exact outer/right or lower borders and any out-of-board point.
- Cursor picking first uses Bevy's camera viewport-to-world conversion, which absorbs window scale factor, viewport, camera translation, and zoom, then passes only the resulting world point into `BoardGeometry`.
- Orientation is selected from the validated North Pawn direction: positive canonical Y places North at the top, so increasing rank labels follow North's forward direction. Files support `a` through multi-letter labels for every schema-supported board width.
- Coordinate labels are named with their full canonical square for inspection/accessibility while showing compact file and rank axes around the board.
- Headless tests cover all four 24x24 corners, interior and negative points, exact border behavior, out-of-range coordinates, both orientations, multi-letter files, and representative round trips without deriving coordinates from rendered entities.

## Acceptance criteria

- Corners, borders, negative world coordinates, and out-of-board clicks behave correctly.
- Conversion is independent of window DPI and camera zoom.
- Board orientation is explicit and labels agree with Pawn directions.
- Headless tests cover representative transforms.

## Cross-cutting concerns

- Do not derive rule coordinates from rendered entity iteration.
