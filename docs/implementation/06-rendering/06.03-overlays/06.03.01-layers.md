## Implementation notes

- Added a semantic overlay model keyed by canonical revision, selected `PieceId`, and hovered coordinate. The renderer rebuilds overlay entities only when that key changes.
- Selection, legal Move destinations, captures, selected-piece attacks, check, governance paths, governance blockers, and illegal hovered destinations use distinct symbols, colors, sizes, and stable precedence values.
- A legal hover runs the canonical reducer against a preview state, then compares selected-piece attack squares and governed settlement IDs to emit separate gained/lost attack and governance overlays.
- Check is the highest ordinary precedence and illegal warnings sit above selection/move marks, so neither can be hidden by routine highlights. Multiple meanings remain present as independently ordered entities and in the canonical coordinate-to-kind cache.
- Hold availability is summarized alongside selected-piece legal counts and hover gains/losses. A complete textual legend is appended to `OverlayText` for the side panel in Task 07.02.01.
- Tests lock precedence, distinct gain/loss symbols, model caching, selected Knight moves/attacks, textual equivalents, and the complete legend.

## Acceptance criteria

- Overlay precedence is deterministic and documented.
- Hover preview distinguishes new and lost attacks/governance.
- Check and illegal self-check warnings cannot be hidden by ordinary highlights.
- Overlay recomputation occurs only when relevant state changes.
