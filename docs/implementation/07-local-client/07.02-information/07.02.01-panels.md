# Task 07.02.01: Build match and settlement panels

Create responsive panels for turn status, clocks, selected piece, action history, match controls, and settlement details.

## Dependencies

- 04.04, 06.01.03.

## Status

- [x] Done

## Implementation notes

- Enabled Bevy's UI feature and added two screen-space information panels. Percentage widths with minimum/maximum bounds, word wrapping, clipped height, and independent header toggles keep board space recoverable from the supported minimum window upward; `I` collapses or expands both panels from the keyboard.
- The match panel names active player, turn, command/mandatory-choice phase, clocks, selection, outcome, and current controls. Check and clocks at or below one minute use prominent `!!! CHECK` and `!! LOW CLOCK` text in addition to styling, so neither condition depends on color perception.
- Each authored settlement entry shows owner, founder identity and current presence, governor identities, human-readable piece/terrain/edge blockers, establishment and production progress against scenario thresholds, established state, produced-Pawn placement readiness, and the supported Pawn's identity/location.
- Recent history is a single text entity containing at most the latest 12 durable transition messages with total/showing counts. It does not spawn an entity per event, while the underlying ordered log remains available for later save/replay work.
- History wording explicitly distinguishes Move/capture, Hold, promotion, production, draw offer/response, turn, settlement, and terminal events. Reducer event order remains unchanged.
- Panel text is cached by canonical revision, selected identity, and history length. Pointer presence over panel surfaces is reported through the existing UI capture boundary so board hover/click handling does not intentionally target covered tiles.
- Tests cover explicit low-clock/check/selection/phase text, every required settlement field, 100-event bounded history slicing, independent collapse state, two-panel/one-history-entity structure, and distinct Hold/draw/promotion/production/terminal history messages.

## Acceptance criteria

- Settlement entries show owner, founder presence, governors/blocker, establishment/production progress, readiness, and supported Pawn.
- Check and low-clock states are prominent but not color-only.
- History distinguishes Move, Hold, promotion, production, draw, and terminal events.
- Panels can collapse to preserve board space.

## Cross-cutting concerns

- Large histories use bounded/virtualized presentation rather than one UI entity per lifetime event.
