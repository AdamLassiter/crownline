## Implementation notes

- The client starts in a modal Crownlines local-setup flow. Introductory, standard, and large authored scenarios are embedded in a stable catalog; PageUp/PageDown selection explains name, board dimensions, expected duration, Pawn double-step, en passant, and authored castling-route count before creation.
- North and South names use keyboard-focusable Bevy editable-text controls. Tab navigates the fields, `X` swaps their North blue/pale and South orange/dark assignments, and `F2` starts. Validation trims names, rejects empty/duplicate names and values over 24 characters, while color assignments remain complete and mutually exclusive.
- Starting a scenario constructs a fresh canonical `MatchState`. A renderer scenario-ID boundary despawns all old scenario visuals and rebuilds tiles, coordinates, pieces, Keeps, settlements, promotion sites, fortifications, edges, and board geometry; a regression test proves only one root and the selected tile count remain.
- `P` opens a settings/pause surface and blocks board commands; P/Escape resumes. `Q` enters a separate resignation confirmation state where Enter confirms and Escape cancels. `D` offers a draw and the opponent answers with Y/N through reducer actions.
- Terminal flow names the configured winner and color, or Draw, plus the exact canonical `OutcomeReason`. `R` rematches with the same scenario and player settings while incrementing a local session identity, recreating revision-zero state, clearing selection, and clearing prior history.
- Setup, pause, confirmation, and outcome states gate the ordinary board interaction system. Menus and every lifecycle transition have keyboard controls and therefore do not depend on precise pointer use.
- Tests cover name correction, preserved rematch settings with fresh session/state, and stale-free scenario visual rebuilding; existing core tests cover typed resignation, draw, and terminal behavior.

## Acceptance criteria

- Setup explains scenario size, expected duration, and enabled special rules.
- Invalid names/colors/settings are corrected before match creation.
- Outcome names winner/draw and exact reason.
- Rematch preserves settings but creates fresh identities and state.
