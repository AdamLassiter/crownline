# Task 07.03.02: Integrate local clocks

Host optional clocks locally with untimed default, 1-180 minute base, and 0-60 second increment.

## Dependencies

- 04.04.01, 07.03.01.

## Status

- [x] Done

## Implementation notes

- Local setup remains untimed by default. `C` enables/disables a clock, `-`/`+` changes base minutes within 1–180, and `,`/`.` changes increment seconds within 0–60; the current values are visible before match creation and validated by construction through core `ClockSettings`.
- Fresh matches and rematches call `start_clocks` only when timing is enabled. Rematches preserve the selected clock settings while constructing fresh full-base canonical clock values.
- A `PreUpdate` host system reads only Bevy's monotonic `Time<Real>::delta`, carries sub-millisecond remainder, and applies whole elapsed milliseconds through `advance_clock`. Partition tests prove that split frame deltas charge the same total as one contiguous delta.
- Clock charging is independent of turn phase, so it continues throughout mandatory promotion and Pawn-placement queues. Setup, explicit pause, resignation confirmation, outcome, and untimed states do not accumulate or later replay elapsed time.
- Ordinary ticks update canonical clock values without adding per-frame history entries. Panels include clock values in their cache key, so display refresh does not depend on gameplay revision changes.
- Every local gameplay, mandatory-choice, resignation, and draw action uses `apply_timed_action` at zero additional elapsed time after the `PreUpdate` charge. Increment therefore applies only to accepted Move/Hold, while all other accepted actions receive no increment.
- Expiration is resolved before Update-stage input and immediately moves the lifecycle to its terminal outcome. An exact-deadline regression verifies the attempted action does not advance the turn.
- No wall-clock timestamp or deadline is stored. Closing or saving captures only canonical remaining milliseconds, so offline duration cannot be charged on resume.

## Acceptance criteria

- Clocks run through mandatory choices, pause in explicit pause state, and stop at terminal outcome.
- Increment applies only after accepted Move/Hold.
- Closing/saving does not consume offline time.
- Expiration prevents a later local command from being accepted.

## Cross-cutting concerns

- Use monotonic runtime timing and avoid frame-rate-dependent subtraction.
