# Task 07.03.03: Implement atomic save/load

Provide manual save slots/files and load validation using the versioned core envelope.

## Status

- [x] Done

## Implementation notes

- Added three platform-local save slots with F5 save, F9 load, and F6 slot selection, plus visible success, failure, and recovery guidance in the match panel.
- Saves use a bounded, versioned JSON client wrapper containing the validated core envelope, authored scenario RON, durable transition history, setup identity, pending phase, and clock state.
- Generalized the core atomic-write pipeline so the host writes a temporary file, synchronizes and reads it back, validates the complete wrapper, and only then replaces the selected slot.
- Load validation checks wrapper/core/schema versions, canonical state hash, scenario identity and validity, names, slot metadata, and payload size before mutating client resources. Loading resets fractional clock time so offline time is never charged.
- Automated coverage round-trips placement and promotion choices, clocks, check, draw offers, and terminal outcomes, and proves a corrupt temporary payload cannot replace a known-good save.

## Dependencies

- 02.03.01, 07.03.02.

## Acceptance criteria

- Save includes scenario, state, action history, clock values, and application/schema versions.
- Write-to-temporary, validate, and atomic-replace protects the previous file.
- Load errors preserve the file and present recovery guidance.
- Round-trip covers pending promotion/placement, check, draw offer, and terminal state.

## Cross-cutting concerns

- Save paths are platform appropriate and user-selected exports cannot escape explicit user intent.
