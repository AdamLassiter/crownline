# Story 07.04: Unified GUI menu system

As a player, I need one polished and organised menu system so every setup,
configuration, persistence, and lifecycle action is discoverable without
memorising hotkeys.

## Status

- [x] Done

## Implementation notes

- One full-window native Bevy menu shell now owns Home, local setup, Settings,
  contextual match/persistence, outcome, confirmation, help handoff, guided
  handoff, and online handoff navigation.
- Shared typed actions provide pointer and focused-key parity. Visible focus,
  disabled tab exclusion, modal precedence, editable text ownership, scroll
  bounds, destructive confirmation, and pending-state locks are explicit.
- Settings uses Apply/Cancel drafts across Display, Accessibility, Controls,
  and Online categories. Local saves expose validated metadata and atomic
  confirmation paths; online controls retain protocol authority.
- [Bug 023](../../bugs/023-menu-controls.md) is resolved by discoverable setup
  controls. [Bug 024](../../bugs/024-online-ui-query-conflict.md), found during
  final live validation, is also resolved.
- Headless regressions, the complete workspace gate, and live 800x480 and
  1280x800 rendering checks pass.
- Task 07.04.08 groups related controls horizontally, distinguishes read-only
  and editable surfaces, unifies Back/Cancel/Quit styling, removes quit
  confirmation, and locks guided scenarios behind the preceding completion.

## Menu information architecture

- Home: New Local Match, Continue/Load Game, Guided Play, Online Play,
  Settings, Rules & Legend, Quit, and version information.
- Local Match: Scenario, Players, Time Control, Back, and Start Match.
- Guided Play: category browser, progress, difficulty, resume/reset/start,
  hints, retry, and completion.
- Online Play: Host, Join, Waiting Room, reconnect, and saved-seat controls.
- Settings: Display, Accessibility, Controls, and Online categories.
- Local match menu: Resume, Save, Load, Settings, Rules, draw controls,
  resignation, and confirmed return Home.
- Online match menu: Resume, Settings, Rules, authoritative draw/resignation
  controls, reconnect state, and finished-room actions.

## Acceptance criteria

- Every menu action is available through a visible pointer control and complete
  keyboard focus navigation.
- Retained shortcuts are optional context-sensitive accelerators which dispatch
  the same typed actions as buttons.
- Menus remain readable without overlap at the supported logical viewport and
  UI-scale bounds.
- Settings use Apply or Cancel semantics and preserve compatible configuration.
- Opening or navigating presentation-only menus never mutates canonical match
  state.
- Local pause stops local clocks; an online match menu clearly states that the
  authoritative clock continues.

## Cross-cutting concerns

- Native Bevy UI only; keyboard accessibility, non-hue state cues, modal input
  ownership, player-safe errors, atomic saves, credential privacy, and
  deterministic state/UI separation.
