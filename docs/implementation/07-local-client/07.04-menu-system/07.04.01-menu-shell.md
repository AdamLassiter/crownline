# Task 07.04.01: Build the menu shell and component system

Create the native Bevy full-window menu shell, typed navigation/action model,
modal ownership, focus behavior, and reusable control presentation.

## Status

- [x] Done

## Implementation notes

- Added a client-only typed route, action, state, and intent boundary so pointer
  controls and focused keyboard activation cannot drift into separate behavior.
- Added one modal full-window native Bevy shell with bounded content width,
  vertical scrolling, persistent navigation guidance, and exclusive pointer
  ownership above the board UI.
- Added reusable action buttons with non-hue focused, selected, destructive,
  pending, and disabled presentation states.
- Headless tests cover deterministic navigation history, hidden/scrollable shell
  construction, and identical pointer/keyboard typed intents.
- Verified with `cargo test -p crownline menu::tests` and Clippy with warnings
  denied.

## Dependencies

- 07.02.01, 07.02.02, Bug 017.

## Acceptance criteria

- Only the visible route and topmost modal receive pointer or keyboard input.
- Buttons expose distinct idle, hovered, pressed, focused, selected, disabled,
  error, and pending states without color-only meaning.
- Tab and Shift-Tab traverse controls, Enter/Space activate, arrows operate
  grouped controls, and Escape navigates back.
- Content scrolls rather than clips at 800x480 logical pixels and all supported
  UI scales.
- Pointer actions and accelerators enter one typed action dispatcher.
- Opening and navigating the empty shell leaves the canonical match hash
  unchanged.

## Cross-cutting concerns

- Input accessibility, screen ownership, state/UI separation, and headless
  presentation tests.
