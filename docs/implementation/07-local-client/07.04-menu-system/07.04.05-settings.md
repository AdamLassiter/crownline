# Task 07.04.05: Implement transactional Settings

Add Display, Accessibility, Controls, and Online settings tabs backed by a
validated draft with explicit Apply and Cancel behavior.

## Status

- [x] Done

## Implementation notes

- Added a four-tab Settings page for Display, Accessibility, Controls, and
  Online configuration using the existing `ClientSettings` format.
- Display offers a supported-size preset cycle and editable custom width/height;
  Accessibility previews bounded UI scale and Reduced Motion immediately.
- Camera controls show the mandatory Shift modifier, capture only the supported
  key set, reject duplicate bindings, and provide a draft-only reset.
- Online settings edit the default WebSocket URL and use a destructive
  confirmation before clearing saved-seat metadata.
- Settings open as a cloned draft. Apply validates and persists before updating
  the primary window and live resources; Cancel restores previewed values and
  leaves the stored file untouched.
- Configuration and menu tests plus Clippy with warnings denied pass.

## Dependencies

- 07.04.01, 01.03.02, 06.02.02, Bug 010.

## Acceptance criteria

- Existing settings files remain compatible without a schema migration.
- Display offers window-size presets plus validated custom width and height.
- Accessibility offers UI scale from 0.75 to 2.5 and Reduced Motion.
- Controls capture the seven existing Shift-modified camera bindings, reject
  conflicts, and reset to defaults.
- Online settings edit the default server URL and confirm forgetting a saved
  seat.
- Apply persists valid settings; Cancel restores all previewed values; a failed
  save preserves the prior configuration and reports an actionable error.

## Cross-cutting concerns

- Compatibility, recoverability, readable scaling, and shortcut conflict
  prevention.
