# Task 07.04.06: Implement match and persistence menus

Move local and online lifecycle, save/load, and outcome actions into
context-aware GUI menus.

## Status

- [x] Done

## Implementation notes

- `P` opens one context-aware match shell. A local match enters the existing
  paused flow and stops its clock; an online match keeps `OnlinePlaying` and
  explicitly warns that authoritative time continues.
- Menu ownership now gates lifecycle hotkeys, board keyboard input, promotion
  input, local persistence hotkeys, and online lifecycle shortcuts so covered
  gameplay cannot act through the overlay.
- Local pause exposes Resume, Settings, Rules, three-slot Save/Load, draw,
  confirmed resignation, and confirmed Return Home controls. Outcome exposes
  the exact result, Rematch, Rules, Home, and direct Quit after Task 07.04.08.
- Save cards use the existing bounded decoder to show Empty, Valid, or
  Unreadable state plus scenario, players, revision, and completion. Occupied
  saves overwrite atomically only after confirmation; active-match loads
  require confirmation and reuse the canonical restoration path.
- Guided and online matches explain why ordinary slots are unavailable.
- Online match controls now include visible pointer buttons for draw responses,
  confirmed resignation, rematch responses, and leaving, all backed by the
  existing authoritative protocol outboxes and pending locks.
- Focused lifecycle, persistence, interaction, and menu tests plus Clippy with
  warnings denied pass.

## Acceptance criteria

- Local pause stops local clocks; an online menu blocks local input while
  explicitly warning that the authoritative clock continues.
- Three slot cards show Empty, Valid, or Unreadable and available scenario,
  player, revision, and outcome metadata.
- Save/load is unavailable for guided and online matches with an explanation.
- Overwrite, active-match replacement, resignation, and abandonment require
  confirmation.
- Loading restores the same canonical hash and pending phase as direct load.
- Draw, resignation, rematch, leave, and outcome controls cannot submit twice
  while pending.

## Cross-cutting concerns

- Atomic persistence, protocol authority, destructive confirmation, and clock
  truthfulness.
