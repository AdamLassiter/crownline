# Task 07.04.08: Refine menu visual hierarchy and guided progression

Replace the remaining undifferentiated vertical presentation with grouped
controls, explicit surface roles, linear guided progression, and direct quit.

## Status

- [x] Done

## Implementation notes

- Home, local scenario navigation, player configuration, time steppers,
  settings tabs and paired values, save/load actions, modal actions, and outcome
  actions now use responsive equal-width horizontal rows where the controls
  form one conceptual choice.
- Read-only information panes use a cool slate fill and border. Editable text
  fields use a distinct green fill and border, while buttons retain the
  established blue interaction states.
- Back, Cancel, and Quit share the same brown exit treatment through
  `MenuEmphasis::Exit`; guided and online Back/Cancel controls use the same
  color token. Destructive match mutations retain their separate red treatment.
- Quit now writes `AppExit::Success` from its typed action immediately. It no
  longer creates or renders a confirmation modal.
- Guided scenario zero is initially available. Every later scenario is locked
  until the immediately preceding catalog entry has persisted completion.
  Locked Start and Resume controls are visibly disabled, ignored by pointer
  input, and removed from tab order; the read-only browser names the required
  preceding scenario.
- Headless regressions cover grouped rows, surface-role colors, shared exit
  emphasis, direct quit, and sequential guided unlocking. Live X11 checks at
  800x480 cover Home, local setup, and a locked guided scenario.

## Dependencies

- 07.04.01 through 07.04.07, 14.01.02.

## Acceptance criteria

- Related controls appear side by side without preventing the route from
  scrolling at the minimum viewport.
- Read-only panes, editable fields, ordinary buttons, exit actions, and
  destructive actions are visually distinguishable without relying on labels.
- Back, Cancel, and Quit use one shared color treatment.
- Quit exits after one explicit activation and never opens a confirmation.
- The completed guided chain and its next scenario are available; later
  scenarios name and enforce their immediately preceding prerequisite.

## Cross-cutting concerns

- Minimum-viewport layout, non-hue semantics, keyboard focus order, persisted
  progression integrity, typed-action parity, and consistent destructive-action
  language.
