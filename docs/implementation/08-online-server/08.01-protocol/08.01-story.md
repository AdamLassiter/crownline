# Story 08.01: Versioned protocol

As client and server developers, we need a bounded, explicit contract for room and match communication.

## Tasks

- [08.01.01 Define HTTP and WebSocket messages](08.01.01-messages.md)
- [08.01.02 Define revisions, acknowledgements, and snapshots](08.01.02-sync-contract.md)

## Dependencies

- 02.02, 02.03.01.

## Acceptance criteria

- Every message has a protocol version and bounded serialized form.
- Stable machine error codes are separate from player-facing text.
- Compatibility and malformed-input behavior is tested.

## Cross-cutting concerns

- Protocol types contain no Bevy types and no raw database records.
