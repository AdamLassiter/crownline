# Task 08.01.01: Define HTTP and WebSocket messages

Define create/join/health requests and WebSocket ready, action, draw, rematch, snapshot, acknowledgement, error, and connection-state messages.

## Status

- [x] Done

## Implementation notes

- Added versioned health, room creation, and room join request/response types plus tagged client/server WebSocket message families for ready, action, draw, rematch, snapshot, acknowledgement, error, and connection state.
- Bounded HTTP bodies and client WebSocket messages, player names, room codes, scenario identifiers, reconnect tokens, and custom clock settings with shared protocol constants and typed validation errors.
- Kept canonical gameplay actions separate from draw and rematch lifecycle commands; draw actions hidden in the generic action envelope are rejected.
- Added stable machine error codes without internal server details, and recoverable decoding for malformed JSON, unknown variants, incompatible versions, and oversized messages.
- Tests round-trip representative HTTP and every WebSocket message family and cover bounds, unsafe identifiers, unknown variants, and future protocol versions.
