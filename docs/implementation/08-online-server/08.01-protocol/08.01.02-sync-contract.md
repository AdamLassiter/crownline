# Task 08.01.02: Define synchronization contract

Require match ID, expected revision, and client-generated idempotency key on state-changing requests; return full authoritative snapshots after accepted actions.

## Dependencies

- 08.01.01, 02.03.02.

## Acceptance criteria

- Duplicate keys return the original result without applying twice.
- Stale revisions return a current snapshot and stable error code.
- Snapshots include scenario identity/hash, canonical state, clocks, room state, and revision.
- Client and server protocol compatibility is checked before joining.

## Cross-cutting concerns

- Full snapshots are bounded for the maximum board and compressed only after measurement.
