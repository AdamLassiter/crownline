# Task 08.02.01: Implement create/join/ready flow

Add accountless room creation, second-seat join, readiness, match start, leave, and terminal/rematch lifecycle.

## Status

- [x] Done

## Implementation notes

- Added an in-memory authoritative room service and HTTP create/join routes using the shared versioned protocol responses and sanitized public errors.
- Room codes use six uppercase characters from an unambiguous alphabet, normalize surrounding whitespace and case on join, and are collision-checked before insertion.
- Host scenario IDs resolve only through a build-installed, parsed, validated, canonically hashed scenario catalog; custom clocks pass the shared protocol bounds before a room exists.
- Each seat receives a distinct opaque credential and all ready, lobby-leave, and rematch operations resolve the credential back to exactly one occupied seat. Raw names remain bounded opaque display data and are serialized rather than interpolated.
- Canonical match state and optional clocks are created only after both occupied seats are ready. Terminal rooms require a canonical outcome, and two rematch acceptances produce a new match ID and fresh state.
- Tests cover case-normalized joining, unambiguous codes, delayed clock start, full-room and impersonation rejection, lobby leave/rejoin, terminal rematch, installed hashes, and invalid host choices.

## Dependencies

- 08.01.02, Epic 05 scenarios.

## Acceptance criteria

- Codes are short, unambiguous, case-normalized, and collision-checked.
- Host choices are validated against installed scenario hashes and clock bounds.
- A seat cannot join twice or impersonate the other player.
- Initial clocks start only after both players are ready.

## Cross-cutting concerns

- Player display names are length-limited, escaped, and not treated as identities.
