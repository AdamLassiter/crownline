# Task 08.02.03: Add request limits and lifecycle cleanup

Bound HTTP/WebSocket input, connection counts, idle pre-game rooms, and repeated failed operations.

## Status

- [x] Done

## Implementation notes

- Applied Axum's body limit before JSON extraction using the shared HTTP byte bound; the protocol decoder independently rejects oversized WebSocket messages before deserialization.
- Added configurable fixed-window create/join IP quotas, per-room operation quotas, maximum room count, total/per-IP connection accounting, and the existing per-room credential-failure throttle.
- Request-window and failed-auth maps are pruned, connection capacity is explicitly released, and room allocation cannot grow beyond the configured maximum.
- Idle cleanup removes only never-started lobbies after the configured timeout and cleans related authentication bookkeeping. Any room that has started remains retained regardless of idle duration for later persistence/recovery handling.
- Limit and cleanup events emit structured kind/scope/count metadata without request bodies, reconnect tokens, or other sensitive payloads.
- Safe small-server defaults can be overridden with `CROWNLINE_MAX_HTTP_BYTES`, `CROWNLINE_MAX_ROOMS`, create/join/room-operation rate variables, connection limits, and `CROWNLINE_PREGAME_IDLE_SECONDS`.
- Tests cover quota reset/pruning, per-IP and global connection release, room-count bounds, idle lobby expiry, and non-expiry of started matches.

## Acceptance criteria

- Oversized and malformed messages are rejected before expensive parsing/work.
- Per-IP and per-room limits protect create/join/auth/action paths.
- Empty, never-started rooms expire after a configured interval; persisted matches do not expire silently.
- Limit events are observable without logging sensitive payloads.
