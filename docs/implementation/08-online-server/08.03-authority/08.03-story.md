# Story 08.03: Authoritative match hosting

As online players, we need one serialized authority to prevent divergent or simultaneous turns.

## Status

- [x] Done

## Implementation notes

- Task 08.03.01 provides bounded per-match actors with total command ordering, revision/idempotency handling, controlled backpressure, failure isolation and durable reload, and idle unloading.
- Task 08.03.02 integrates authenticated-seat authorization, server receipt-order wall clocks, canonical reducer/journal execution, exact timeout semantics, persisted deadlines, and atomic transition preparation.
- Task 08.03.03 adds authenticated WebSocket reconnection, commit-before-broadcast snapshots, bounded latest-value delivery, room-event recovery, terminal/rematch lifecycle synchronization, and failure-independent canonical progress.

## Acceptance criteria

- Commands for one match execute in a total order; separate matches remain concurrent.
- Server core validation is the only path to canonical state mutation.
- Connection loss does not pause an active online clock or corrupt the match.

## Cross-cutting concerns

- Backpressure, race testing, clear time authority, and task-failure containment.
