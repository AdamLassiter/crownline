# Task 08.03.01: Implement per-match command serialization

Route room commands through one bounded queue/actor per active match and return revisioned results.

## Status

- [x] Done

## Implementation notes

- Added a registry that lazily loads exactly one Tokio mailbox/worker per match ID and drops the global registry lock before any command execution.
- Each bounded mailbox accepts commands with `try_send`, returns a controlled retryable saturation error, and serializes revision checking and execution into one total order while separate workers remain concurrent.
- Actors return full revisioned mutation results, current snapshots for stale submissions, stable rejections, and the original bounded cached result for duplicate idempotency keys.
- Fatal executor failures are logged without command payloads, close only the affected mailbox, and evict that actor so the next submission reloads its state through the durable loader abstraction.
- Idle registry entries can unload independently; removing a sender stops only the in-memory worker and leaves durable loader state untouched.
- Race tests prove two simultaneous same-revision commands accept at most one transition. Additional tests cover deterministic queue saturation/backpressure, fatal recovery/reload, and idle unload/reload.

## Acceptance criteria

- Simultaneous same-revision submissions produce at most one accepted transition.
- Queue saturation returns a controlled retryable error.
- Actor failure is contained, logged, and recoverable from persisted state.
- Idle actors can unload without deleting durable matches.

## Cross-cutting concerns

- Never hold global room locks during reducer or database work.
