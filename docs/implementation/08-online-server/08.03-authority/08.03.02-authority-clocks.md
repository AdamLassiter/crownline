# Task 08.03.02: Integrate authoritative rules and clocks

Authorize the seat, advance the server clock to receipt order, resolve timeout, apply the core action, and prepare one atomic persistence transition.

## Status

- [x] Done

## Implementation notes

- Added a concrete per-match executor that checks the authenticated seat against the action actor and rejects non-playing or terminal phases before canonical mutation.
- Actor commands capture server wall-clock receipt time before queueing and decision time immediately before execution; client timestamps are neither accepted nor consulted.
- Clocked execution derives elapsed milliseconds from the persisted wall-clock anchor, so restart downtime counts. The core clock transition resolves exact-deadline timeout before the action and applies increment only after an accepted Move or Hold.
- Wrong-seat, inactive-phase, stale-revision, expired-time, and illegal-action outcomes remain distinct. A timeout mutates the canonical state exactly once; later requests see the terminal inactive phase.
- Each accepted action or timeout is first applied to a cloned journal, then exposed as one prepared persistence unit containing canonical state, append-only journal, wall-clock anchor/deadline, and receive/decision timestamps.
- Restore replays the journal and rejects state divergence before serving the match. Tests cover transactional authorization/errors, exact timeout and restart restore, elapsed charging, increment, next deadline, and prepared-unit contents.

## Acceptance criteria

- Wrong-seat, inactive-phase, expired-time, stale, and illegal actions return distinct errors.
- A deadline reached before command acceptance results in timeout exactly once.
- Increment and next deadline are computed only after accepted Move/Hold.
- Server downtime counts by restoring persisted wall-clock deadlines.

- Record server receive/decision timestamps for diagnostics, never trust client timestamps.
