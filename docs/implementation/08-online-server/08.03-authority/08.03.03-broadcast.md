# Task 08.03.03: Broadcast snapshots and recover connections

Broadcast committed snapshots and room events to current seats and serve the latest state on authenticated reconnect.

## Dependencies

- 08.03.02, 08.04.02.

## Acceptance criteria

- Broadcast occurs only after persistence commits.
- Slow/disconnected clients cannot block match progress.
- Reconnect receives current revision, state, clocks, and outstanding draw/rematch state.
- Snapshot send failures do not roll back accepted actions.

## Cross-cutting concerns

- Bound per-connection outbound queues and favor latest snapshots over stale ones.
