# Task 08.04.02: Commit and restore matches

Commit snapshot, clock/deadline, revision, outcome, and action journal in one transaction and restore active matches after restart.

## Status

- [x] Done

## Implementation notes

- Added a match repository that registers initial authority images and commits the revisioned snapshot, latest append-only action, state hash, clock anchor/deadline, outcome, and match pointer in one constrained SQLite transaction.
- Any action-row failure rolls back the newly inserted snapshot and leaves the match revision unchanged; composite foreign keys prevent a journal/current revision without its corresponding snapshot.
- Startup now opens the configured database, migrates it, restores every unfinished match before building the router, and retains the repository/restored authorities for subsequent actor/reconnect wiring.
- Each restore validates installed scenario identity/hash, UUID/revision metadata, canonical state hash, and full journal replay. Invalid matches enter a migration-controlled quarantine table with a stable reason code while healthy matches continue.
- Persisted wall-clock anchors survive restart, so the next server receipt charges downtime. Integration tests compare uninterrupted and restored revision, hash, and effective clock values after identical later input.
- Added file-reopen, transaction-rollback, mixed healthy/corrupt quarantine, and clock-aware restart tests, plus documented WAL-safe backup and restore procedures in `docs/server-operations.md`.
