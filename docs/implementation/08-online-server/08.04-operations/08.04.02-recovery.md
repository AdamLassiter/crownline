# Task 08.04.02: Commit and restore matches

Commit snapshot, clock/deadline, revision, outcome, and action journal in one transaction and restore active matches after restart.

## Dependencies

- 08.04.01, 02.03.02, 08.03.02.

## Acceptance criteria

- A crash cannot expose a journal revision without its matching snapshot or vice versa.
- Startup validates state/hash before accepting reconnections.
- Corrupt matches are quarantined and reported without blocking healthy rooms.
- Restart integration tests prove identical revision, hash, and effective remaining time.

## Cross-cutting concerns

- Provide documented SQLite backup/restore procedures.
