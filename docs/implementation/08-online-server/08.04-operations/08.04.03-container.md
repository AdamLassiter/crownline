# Task 08.04.03: Package and health-check the server

Build a minimal multi-stage Linux container with non-root execution, SQLite volume, environment configuration, and graceful signals.

## Status

- [x] Done

## Implementation notes

- Added a Rust 1.95 multi-stage Docker build whose Debian slim runtime contains only the release server, CA certificates, and health-probe client. It runs as the dedicated `crownline` UID/GID 10001 with a mode-0700 SQLite volume and no compiler, source, or build cache.
- Added a Compose deployment bound to loopback by default, a persistent named volume, explicit public URL/log configuration, an init process, a stop grace period longer than the application drain, and the image's SIGTERM/health metadata.
- Health responses now report process liveness and database readiness independently. `/health/live` avoids the database and marks it not checked; `/health/ready` and `/health` run a bounded schema/SQLite quick check and return HTTP 503 when degraded.
- Native SIGINT and Unix SIGTERM handling stops listener acceptance, drains requests and WebSockets for the configured 1-300 second bound, then closes remaining connections and drops the SQLite-owning application state.
- Expanded operator documentation for bind/public URLs, TLS/WebSocket proxying, database path and ownership, stdout logs, volumes, health routing, backup/restore, graceful stops, and schema-safe upgrades.
- Release CI now scans locked dependencies and the built runtime image for high/critical vulnerabilities with a commit-pinned Trivy action.
- Verified a real native SIGTERM lifecycle, built and ran the final image as UID/GID 10001, confirmed readiness from inside the container, confirmed compiler tools are absent, and validated the Compose configuration.
