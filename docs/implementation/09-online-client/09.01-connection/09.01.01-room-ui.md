# Task 09.01.01: Build create/join/ready screens

Add online menu, server URL selection, host settings, room code entry/copy, waiting room, and readiness controls.

## Status

- [x] Done

## Implementation notes

- Added an F3 online entry point beside local setup, with separate menu, host, join, and waiting-room presentations built from Bevy UI and editable keyboard-focus fields.
- Hosts select directly from the installed authored scenario catalog, whose metadata identifies the default, and configure the same validated untimed or bounded base-plus-increment clocks used by the protocol.
- Added a capacity-one background HTTP worker with a ten-second timeout, disabled redirects, bounded response bodies, shared protocol validation, and create/join requests that never block the Bevy update loop.
- Server selection accepts `wss://` remotely and permits plaintext `ws://` only for loopback. User info, query data, and fragments are rejected; HTTP room endpoints are derived without carrying WebSocket path data.
- Join input removes whitespace/hyphens and uppercases before shared validation. Server bodies are mapped to fixed player-safe messages rather than displaying untrusted or internal response text.
- Waiting rooms show the room, match, seat, credential-presence, readiness, and invitation controls. Clipboard invitations contain only the normalized room code and optionally a sanitized server origin, never the reconnect token.
- Ready selection remains in the lobby and cannot switch to gameplay. Task 09.01.02 consumes that intent through the authenticated WebSocket and only an authoritative started snapshot may open the match screen.
- Tests cover normalization, loopback/TLS policy, unsafe URL rejection, credential-free invitations, safe error mapping, authored default discovery, incompatible responses, and the snapshot-gated ready transition.
