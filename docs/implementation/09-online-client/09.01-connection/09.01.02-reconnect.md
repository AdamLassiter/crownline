# Task 09.01.02: Implement authenticated reconnect

Store seat credentials in client settings and reconnect with bounded exponential backoff after transient loss or application restart.

## Status

- [x] Done

## Dependencies

- 09.01.01, 08.03.03.

## Acceptance criteria

- UI distinguishes connecting, connected, retrying, offline, rejected, and terminal states.
- Backoff has a cap, jitter, and explicit manual retry/cancel controls.
- Reconnect replaces local canonical state with the authenticated snapshot.
- Credential deletion is available and logs never expose the token.

## Implementation notes

- Added a dedicated authenticated WebSocket worker with bounded command/event channels. The Bevy frame loop never performs credential-store calls, socket I/O, or retry sleeps.
- New and restored seats authenticate using a token-bearing first message rather than a URL. Remote endpoints require `wss://`; plaintext `ws://` remains restricted to loopback, and URL credentials, queries, and fragments are rejected.
- Transient failures retry with exponential delays starting at 500 ms, bounded to 30 seconds, and independently jittered by up to 20%. The persistent status strip distinguishes connecting, connected, retrying, offline, rejected, and terminal states and exposes `T` manual retry, `X` retry cancellation, and `F` deliberate credential deletion.
- Settings persist only room/match/seat/server metadata and a random credential locator. The reconnect token is stored through macOS Keychain, Windows Credential Manager, or Unix Secret Service when available. If that operation fails, the worker uses the platform-local Crownlines data directory and forces the individual `credentials/<locator>.secret` file to user-read/write `0600` on Unix; `settings.ron` is likewise forced to `0600` on Unix.
- Application startup loads the locator on the worker, restores the private token, reconnects automatically, and replaces the displayed scenario and canonical match state only after protocol validation, authenticated match-ID validation, and installed scenario-hash validation.
- Snapshot adoption clears local selection, presentation transition queues, and local notice history so stale local presentation state cannot survive an authoritative replacement. Local reducers and clocks remain disabled in the separate online-playing flow.
- Reconnect tokens use a redacted debug representation and are never included in tracing fields, settings serialization, status copy, or room invitations.
- Tests cover jitter bounds and the retry cap, TLS/URL policy, fallback credential round-trip/deletion and Unix file mode, and proof that serialized saved-seat metadata omits the token. The workspace test and strict Clippy gates pass.

## Cross-cutting concerns

- Use OS-protected credential storage where available, with documented fallback permissions.
