# Task 09.02.02: Reconcile authoritative snapshots

Validate protocol/scenario compatibility, replace canonical state, and rebuild affected ECS/UI projection when a newer snapshot arrives.

## Status

- [x] Done

## Implementation notes

- Added a per-match snapshot identity tracker covering match ID, scenario ID, canonical revision, and state hash. Every decoded server message now passes an explicit protocol-version check before it can reach the Bevy event boundary.
- Snapshot reconciliation validates redundant state metadata, the authenticated match ID, the installed scenario ID/hash, and canonical state hash before classifying the update. A first authenticated snapshot and any newer revision replace canonical resources; older revisions are ignored.
- Equal revisions compare both the prior authoritative hash and a freshly calculated hash of the displayed canonical state. Matching snapshots are lifecycle-only no-ops; any mismatch emits a fixed diagnostic, clears the uncertain pending intent, and repeatedly requests a clean authenticated reconnect until the bounded command channel accepts it.
- A forced reconnect resets the snapshot tracker so the returned authenticated snapshot becomes a clean replacement instead of repeating the equal-revision divergence. Scenario changes within one tracked match and incompatible snapshots are rejected without mutating the board.
- Replacement writes only scenario and canonical match resources; network data is never deserialized into ECS entities. Existing rendering systems rebuild their projection from those resources.
- Selection survives only when its stable piece still exists, belongs to the active player, the match is non-terminal, and the phase accepts a command. Hover survives only while its coordinate remains within the installed board. Camera transforms and client settings are not touched.
- Local transition queues and notice history clear on replacement so presentation state cannot claim an unacknowledged transition. Choice projection keys now include scenario, revision, and complete turn phase, allowing an equal-numbered reconnect into promotion or Pawn placement to reconstruct the correct mandatory controls.
- Tests cover older/equal/newer classification, equal-revision divergence, protocol-version inspection, valid/invalid selection and hover preservation, and mandatory-choice projection invalidation at an unchanged revision.

## Acceptance criteria

- Older snapshots are ignored; equal revisions are hash-checked; newer snapshots replace state.
- Hash mismatch at equal revision produces a diagnostic and forced resync.
- Selection/hover clears if invalid while camera and user settings persist.
- Reconnect during any mandatory choice reconstructs the correct controls.

## Cross-cutting concerns

- Never deserialize network data directly into ECS entities.
