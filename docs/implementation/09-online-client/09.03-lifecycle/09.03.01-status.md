## Implementation notes

- Added a dedicated online-match status surface naming the authenticated seat, active player, command versus mandatory-choice phase, pending-command state/attempts, local transport state, and authoritative room/opponent connection state.
- Each accepted first/newer/equal snapshot emits a presentation-only clock anchor containing canonical remaining times, active player, room state, phase, and terminal status. Network messages never update the clock presentation before protocol and snapshot reconciliation succeed.
- A Bevy monotonic-time system advances only the visible estimate for the active player. It does not mutate `MatchState`, submit a timeout, or infer an outcome when the display reaches zero; the label explicitly says it is awaiting the server.
- `OpponentDisconnected` continues the estimate and is labeled “opponent disconnected; clock continues.” Local WebSocket retry/offline state also does not imply an authoritative pause.
- Ordinary authoritative drift eases toward the newest server values over 350 ms while both target and display continue counting. Terminal snapshots replace the estimate immediately, so server receipt/outcome ordering wins over smoothing and presentation.
- The existing information panel labels online canonical values as “Clocks at last server snapshot,” avoiding a second apparently-live countdown. Untimed matches remain explicit.
- Tests cover visible zero without local terminal state, continued countdown during opponent disconnect, eased ordinary correction, immediate terminal replacement, and distinct room/transport/phase labels.
