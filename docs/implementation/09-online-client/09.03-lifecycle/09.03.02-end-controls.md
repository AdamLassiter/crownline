# Task 09.03.02: Implement draw, resign, and rematch UI

Expose draw offer/response, confirmed resignation, terminal summary, leave, and post-match rematch negotiation.

## Status

- [x] Done

## Implementation notes

- Added a dedicated online lifecycle surface driven only by reconciled canonical state and typed rematch events. It displays one outstanding draw offer at most, distinguishes a self-authored offer from an opponent offer, and exposes `D` offer plus `Y` accept / `N` decline only when valid.
- Draw offer/response uses the protocol’s separate `Draw` envelope. Resignation uses canonical `Action::Resign`, as defined by the protocol/core boundary, and requires `Q` followed by `Enter`; `Escape` cancels. Confirmation rechecks authoritative turn state and is unavailable after any terminal outcome.
- Match controls have a separate bounded outbox/pending record from board input while sharing the authenticated socket worker. Each control keeps its original match, revision, and idempotency key across timeout retries, and board/control mutations serialize when raised together.
- Terminal presentation names the exact canonical outcome reason and winner/draw result. It disables resignation, exposes `L` leave, and shows rematch request/waiting/accept/decline/accepted states from typed server messages.
- `R` requests a rematch or accepts the opponent’s request; `N` declines. Both seats must accept on the server. `Accepted` forces both clients to reauthenticate, accepts the server’s new match ID as a clean snapshot boundary, rebuilds fresh canonical state, and persists the new ID against the same room/seat credential. Scenario and clock settings remain server-owned room configuration.
- Leaving a finished room sends the versioned `Leave` message, closes the local connection, deletes the local seat credential, and returns to setup. The server’s finished-room leave path does not remove the room or its durable result.
- Tests cover active/non-terminal resignation gating, exactly one visible draw offer with opponent choices, exact terminal reason/winner/rematch/leave copy, and the distinct Draw, canonical Resign, and Rematch envelopes with unique mutation keys. Existing server tests cover two-seat rematch creation and durable terminal persistence.

## Acceptance criteria

- At most one outstanding draw offer is shown with accept/decline choices.
- Resignation requires confirmation and is disabled after terminal state.
- Rematch requires both seats, reuses room settings, and creates a new match identity/state.
- Leaving a finished room does not delete its durable result.

## Cross-cutting concerns

- Match-control messages remain separate from board-action revision handling where specified by protocol.
