# Task 10.01.02: Build golden replay fixtures

Record small, reviewed journals that exercise complete opening-to-outcome paths and difficult combined transitions.

## Status

- [x] Done

## Implementation notes

- Added six checked-in format-1 golden journals with fixed application/scenario versions, idempotency keys, elapsed inputs, event lists, and canonical hashes. The introductory, standard, and large authored scenarios are each represented.
- The inventory covers checkmate, timeout, resignation, agreed draw, and threefold repetition. Each test reconstructs the initial state and reapplies every record, checking the before/after revision, exact ordered events, and resulting hash before checking the terminal outcome.
- Added a compact combined scenario and journal that claims and establishes a governed settlement, promotes a surviving Pawn, produces a new Pawn, uses a deployed Pawn double-step, passes through check and escape, disrupts governance continuity, and ends by resignation.
- Added a deterministic generator example and a fixture compatibility policy. Golden changes must carry a semantic compatibility note describing changed actions, events, hashes, formats, scenarios, and persisted-journal compatibility; the initial baseline note is recorded with the fixtures.
- Fixtures contain no timestamps, random IDs, names, credentials, or host data. The golden suite passes independently and as part of the workspace test gate.

## Acceptance criteria

- Fixtures cover each terminal reason and each scenario.
- At least one fixture combines governance disruption, production, promotion, check, and a special Pawn rule.

- Fixture updates require an explicit compatibility note.
