# Task 10.03.00: Implement structured local playtest capture

Provide a privacy-preserving, explicit local record for the quantitative and qualitative evidence required by scenario validation and balance playtests.

## Status

- [x] Done

## Implementation notes

- Added an in-memory recorder for local matches and explicit `F8` JSON export to the platform `Crownlines/playtests` data directory. Online play is excluded and no export or upload occurs without the key command.
- Every versioned report contains application/build identity, scenario ID/schema/canonical hash, session/start/final revision, partial-load marker, turn count, active/paused/mandatory-choice duration, first capture/check/settlement contact, per-side claim/production/promotion/check counts, per-side west/centre/east movement, terminal outcome, and the accepted action/event/canonical-state-hash trace.
- Added blank structured review fields for governance clarity, growth speed, economic conflict, promotion pressure, downtime, major-piece overload, checkmate viability, and consented observations. Reports deliberately exclude names, settings, saves, online addresses/codes, and credentials.
- Routed accepted local board, mandatory-choice, draw/resignation, and terminal clock transitions into a recorder-only queue without changing presentation order or recording authoritative online snapshots. Loaded/nonzero revisions are explicitly marked partial.
- Exposed export status in the match panel, documented the control and exact privacy boundary in the player guide/privacy statement, and added `docs/playtesting.md` for side-swapped pairing, qualitative review, aggregation, and hypothesis/follow-up tuning discipline.
- Added regressions for required metric derivation, versioned JSON round-trip, absence of identifying/credential fields, and partial-load marking.

## Dependencies

## Acceptance criteria

- A local report captures every quantitative field required by Task 10.03.01 from accepted canonical transitions.
- Export is an explicit local action and contains no player identity, room data, credential, or automatic network path.
- Qualitative prototype questions and side-swapped pair procedure are defined next to the evidence format.
- Loaded or discontinuous sessions cannot silently present themselves as complete matches.

## Cross-cutting concerns

- Versioning, canonical hashes, atomic writes, bounded personal data, accessibility of export status, and no telemetry.
