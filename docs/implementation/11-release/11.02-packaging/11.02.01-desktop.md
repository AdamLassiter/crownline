# Task 11.02.01: Package desktop clients

Create CI release jobs and archive layouts for Linux, Windows, and macOS clients.

## Status

- [ ] In progress

Completion is blocked on executing the tag workflow against native Linux,
Windows, Intel macOS, and Apple Silicon macOS runners and archiving the resulting
clean-unpack, signing-status, checksum, and provenance evidence.

## Implementation notes

- Added a tag-only four-target workflow for native Linux x86-64, Windows x86-64, macOS Intel, and macOS Apple Silicon release builds. Every job packages on its native runner, unpacks into a clean directory, invokes the packaged `--version` path, attests provenance, and uploads the ZIP plus SHA-256 checksum.
- Added deterministic `scripts/package_desktop.py`: fixed timestamps, sorted assets, a single version/target root, executable mode preservation, Cargo/tag version agreement, complete runtime assets, project and font licenses, third-party notices, player/privacy docs, and source/version/target `BUILD-INFO.txt`. Settings, credentials, saves, and build intermediates are not inputs.
- Added client `--version`/`-V` output and application version plus abbreviated build revision in the visible window title. Release builds receive the full source revision through `CROWNLINE_BUILD_REVISION`; local builds identify themselves as development. Runtime asset discovery prefers the executable's sibling `assets` directory and retains the repository-relative development fallback, so launch does not depend on the caller's working directory.
- Added optional pre-package Authenticode and Apple hardened-runtime signing, plus Apple notarization when the complete release secret set is present. Pull requests cannot trigger the workflow or access its secrets; only the final tag publication job receives content-write permission.
- Documented the archive contract, local command, checksum/provenance behavior, target matrix, secret names, and unsigned-release disclosure policy in `docs/release-process.md`.
- Implementation and the local Linux clean-archive smoke are complete. Per [Bug 012](../../bugs/012-premature-packaging-completion.md), the task remains in progress until a trusted tag proves every native matrix target.

## Dependencies

## Acceptance criteria

- Each archive runs from an unpacked clean environment and locates all assets.
- Version/build metadata is visible in the client.
- Archives contain licenses/notices and no development saves/settings.
- Checksums are published; platform signing/notarization is used when credentials are available.

## Cross-cutting concerns

- Signing secrets are release-environment secrets and unavailable to pull-request jobs.
