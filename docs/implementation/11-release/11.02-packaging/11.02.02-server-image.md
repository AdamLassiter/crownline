# Task 11.02.02: Publish the server image

Build, scan, tag, attest, and publish the Linux server container for the release revision.

## Status

- [ ] In progress

Completion is blocked on a trusted release tag successfully publishing the
immutable GHCR coordinates, digest, scan records, SBOM, and attestations.

## Implementation notes

- Added a tag-only GHCR publication workflow that verifies the semantic tag against Cargo, builds one exact candidate, and refuses to replace existing application-version or full-source-revision tags. After all gates, the same image digest is also assigned the moving `stable` tag.
- Added OCI title, description, version, revision, source, and license labels through explicit Docker build arguments and pinned both Docker base-image manifest digests. Publication records give operators the digest-pinned image reference rather than treating a tag as deployment identity.
- Added a real pre-push smoke with a fresh mounted named volume: the container must execute as UID 10001, create a non-empty SQLite database, reach Docker `healthy`, and return a successful readiness response. Locally rebuilt and repeated that smoke against the release Dockerfile, including all OCI label values.
- Added a commit-pinned Trivy release gate and complete image plus locked-source JSON records. HIGH/CRITICAL image or dependency vulnerabilities and HIGH/CRITICAL restricted/forbidden repository license findings block publication; no suppression exists. A CycloneDX image SBOM is produced from the same candidate.
- Added GitHub/Sigstore image provenance and SBOM attestations attached to the GHCR digest. The shared GitHub release receives the SBOM, image/source scan JSON reports, and a release record containing immutable/moving tags, digest, source revision, configuration reference, database upgrade sources, verified-backup requirement, and rollback warning.
- Documented immutable tag behavior, vulnerability/license severities, exception requirements, evidence filenames, and the trusted-tag boundary in `docs/server-release-policy.md`. Publication cannot run from a pull request or ordinary branch push.
- Implementation and the local pre-push image smoke are complete. Per [Bug 012](../../bugs/012-premature-packaging-completion.md), the task remains in progress until registry publication supplies the external evidence required by its acceptance criteria.

## Acceptance criteria

- Immutable version and source-revision tags are available alongside an optional moving stable tag.
- Image starts as non-root and reports healthy with a mounted test database.
- Vulnerability/license scan results meet the documented release policy.
- SBOM, digest, configuration reference, and upgrade notes accompany publication.

## Cross-cutting concerns
