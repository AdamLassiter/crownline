# Story 11.03: Compatibility and release gate

As a release owner, I need explicit go/no-go evidence and safe evolution rules.

## Tasks

- [11.03.01 Define compatibility and migration policy](11.03.01-compatibility.md)
- [11.03.02 Execute release-candidate verification](11.03.02-release-candidate.md)

## Dependencies

- 11.01, 11.02, Epic 10.

## Acceptance criteria

- Save, scenario, protocol, and database version policies state supported upgrade paths.
- A release checklist records automated results, platform smokes, online recovery, licenses, and known issues.
- Rollback does not silently open data written by an incompatible newer version.

## Cross-cutting concerns

- Compatibility promises are conservative until real upgrade history exists.
