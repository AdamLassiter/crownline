# Task 12.01.01: Define the fog rules and scenario contract

Specify the exact visibility semantics and add versioned scenario configuration for fog-enabled matches.

## Status

- [ ] Not started

## Dependencies

- 02.01.01, 02.01.02, 03.01.01, 04.01.01, 04.04.02.

## Scope

- Add an optional scenario fog configuration with a positive `vision_radius`; absence preserves perfect information.
- Formalize `Undiscovered`, `Explored`, and `Visible` from the story contract, using Chebyshev radius and no vision blockers.
- Define which static facts become permanent knowledge and which dynamic/public facts remain current-only or globally public.
- Define vision timing at match creation and after movement, capture, promotion, production, Pawn placement, rematch, and load/reconnect reconstruction.
- Record the accepted action-result inference boundary and prohibit canonical legal-move lists from being exposed as a shortcut.
- Reject zero, overflowing, or board-incompatible radius values and unsupported future fog schema variants with actionable validation errors.

## Acceptance criteria

- Scenario authors can enable fog with one validated radius and can leave it disabled explicitly or by backward-compatible omission.
- Two implementations following the contract produce the same visible coordinate set for every board edge, radius, piece position, and player.
- The contract unambiguously classifies terrain, sites, edges, friendly/enemy pieces, settlements, promotion state, check, clocks, draw state, and outcomes.
- Existing scenario canonical hashes remain unchanged when the optional field is absent.
- Documentation names Chebyshev distance, radius 3 as the first tuning baseline, and non-blocking terrain as deliberate initial decisions.

## Cross-cutting concerns

- Schema/version compatibility, deterministic coordinate ordering, bounded radius validation, and a documented extension point for later line-of-sight rules.
