# Task 12.01.02: Track deterministic exploration knowledge

Persist what each player has explored and derive current vision from canonical piece positions.

## Status

- [ ] Not started

## Dependencies

- 12.01.01, 02.02.01, 02.02.02, 02.03.01, 02.03.02.

## Scope

- Add independent North/South explored-coordinate masks to canonical match state for fog-enabled scenarios; perfect-information state retains its compact legacy representation.
- Initialize every mask as undiscovered, then union in each starting army's current vision before the first player projection.
- Recompute current vision deterministically from living friendly pieces and union it into exploration after every accepted transition that can change a piece or create a fresh match.
- Use a board-bounded bitset or equivalently deterministic ordered representation; never serialize hash iteration order.
- Include explored knowledge in canonical hashing, save snapshots, journals, golden replay verification, rematches, and explicit migrations.
- Keep current vision derived/revision-cached rather than serialized as a second source of truth.

## Acceptance criteria

- A square changes only `Undiscovered -> Visible`, `Visible -> Explored`, `Explored -> Visible`, or remains in its current state; it never returns to `Undiscovered`.
- North and South exploration histories are independent and replay identically from the same scenario and actions.
- Captures remove the captured piece's future vision, while promotion and produced-Pawn placement retain or add vision at the authoritative transition boundary.
- Save/load, journal replay, rematch, and state-hash tests cover both fog-enabled and perfect-information matches.
- Visibility computation is bounded by board area times friendly piece count and meets the existing 24x24 responsiveness budget.

## Cross-cutting concerns

- Canonical determinism, migration safety, compact bounded storage, revision-keyed caches, and no dependency from core rules on Bevy or networking.
