# Task 12.01.03: Build seat-safe state projections

Create the sole API through which a local or remote seat can observe a fog-enabled canonical match.

## Status

- [x] Done

## Implementation notes

- Added versioned, seat-explicit `PlayerView` projection as the single canonical-to-observer API. It carries only a projection revision/hash, public match facts, ordered known static facts, all own pieces, currently visible enemies, permitted dynamic settlement/promotion/en-passant facts, and own castling rights.
- Undiscovered squares/sites are absent; static edges appear after either endpoint is explored. Enemy pieces, lineage, special rights, candidate state, and settlement dynamics disappear outside current vision, while hidden piece references inside an otherwise permitted settlement are independently filtered.
- Projection hashes serialize only the projection and cannot expose or compare scenario/state canonical hashes. Ordered square/edge arrays avoid structured JSON map keys and keep serialization deterministic and wire-safe.
- Added projection-only hover explanations, own selection/move and Pawn-placement intent candidates, private mandatory-choice summaries, and filtered transition events. Candidate APIs consult only disclosed visible facts and never call canonical legal-move generation; every authenticated intent failure collapses to `IllegalIntent`.
- Generated-state disclosure tests cover both seats at equal revisions and assert every disclosed square, edge, piece, settlement, candidate, and referenced identity is permitted. Serialization and Debug regression checks exclude hidden enemy IDs/kinds, undiscovered terrain, canonical hashes, and canonical placement lists; perfect-information projection still exposes the complete board.

## Scope

- Introduce a versioned `PlayerView`/seat-projection model containing the viewing player, projection revision/hash, explored static map facts, currently visible enemy pieces/dynamic facts, all friendly pieces, and declared public match facts.
- Redact undiscovered terrain/sites/edges and all non-visible enemy piece identity, kind, coordinate, lineage, special rights, promotion candidacy, governance, and settlement progress.
- Reveal a static edge only after at least one adjacent square is explored; reveal dynamic edge/site ownership only while its governing square is visible.
- Provide projection-safe selection, hover, textual explanation, and intent-candidate queries. Never compute a UI preview from canonical hidden occupancy and then merely hide its sprite.
- Return one opaque rejection for hidden-state-dependent invalid intents and document action-result inference as an accepted limitation of this rules variant.
- Replace externally comparable canonical hashes with projection hashes; canonical hashes remain authority/persistence internals.

## Acceptance criteria

- Serializing or debug-formatting either player's projection contains no forbidden enemy coordinate, piece ID/kind, dynamic settlement fact, canonical hash, or undiscovered terrain marker.
- The two projections can differ at the same canonical revision while each projection hash is stable and deterministic.
- Own pieces and public check/clock/draw/outcome facts remain sufficient to operate the turn UI.
- Property tests generate states and prove every disclosed field is permitted by the visibility classification table.
- Projection APIs accept an authenticated seat explicitly; there is no default or spectator view that falls back to canonical truth.

## Cross-cutting concerns

- Privacy by construction, deterministic redaction, bounded payloads, opaque errors, and separation between canonical rules and player-observable models.
