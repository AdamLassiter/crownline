# Task 12.01.05: Deliver private online seat views

Send independently redacted authoritative views to each authenticated online seat and preserve them across reconnect and restart.

## Status

- [x] Done

## Implementation notes

- Advanced the exact-match client/server protocol to version 3. Perfect-information scenarios retain the existing canonical snapshot variants; fog scenarios use distinct seat snapshot, acknowledgement, and error variants containing a validated `PlayerView` and projection hash but no canonical state or hash.
- The server authenticates a room seat and resolves its installed scenario before any snapshot projection. Initial connection, subscription updates, lag recovery, accepted/duplicate mutations, stale revisions, ordinary rejections, reconnect, and rematch startup all construct the wire view for that authenticated seat at the final send boundary. Unauthorized, malformed, wrong-match, and wrong-seat requests receive no snapshot or hash oracle.
- Canonical snapshots, exploration, journals, deadlines, and hashes remain inside the actor, watch hub, repository, and recovery paths. Public lifecycle broadcasts contain no match state. Projection failures return fixed public copy and log no payload.
- The client validates projection metadata/hash, reconciles equal revisions by projection hash, installs the private view directly into fog presentation, and maintains only a disclosed public-state surrogate needed by existing online input/status systems. Online playtest records, transition notices, and local metadata receive no canonical online payload.
- Added two-seat wire assertions proving North/South projections differ, enemy pieces obey current visibility, and serialized fog messages omit canonical state hashes and exploration. Client tests cover projection-hash ordering and prove the disclosed surrogate contains exactly the projection's pieces. Existing actor unload/reload, database restart, reconnect, idempotency, stale-revision, rematch, and exploration persistence gates continue to pass.

## Scope

- Version the protocol so fog matches carry seat projections and projection hashes instead of full canonical snapshots and canonical hashes.
- Authenticate the seat before projection, including create/join, ready, reconnect, stale-revision response, mutation result, terminal control, and rematch paths.
- Replace shared full-snapshot broadcast payloads with revision notifications or separately constructed North/South messages; never place canonical truth in a subscriber-visible channel.
- Keep full state, exploration masks, canonical hashes, deadlines, and journals in server persistence while sending only the requesting seat's current projection.
- Reconstruct the exact seat view after disconnect, process restart, stale intent, and equal-revision reconciliation.
- Prevent logs, metrics, panic diagnostics, invitation data, active-match playtest exports, and client save metadata from carrying hidden canonical payloads. Permit a full-truth replay only after terminal state under an explicit documented policy.

## Acceptance criteria

- Captured North and South traffic for the same revision differs as expected and contains no information forbidden to either seat.
- No unauthenticated, wrong-seat, stale, or malformed request receives a projection or hash oracle.
- Duplicate/idempotent results return the same seat projection; stale results return the current projection for that authenticated seat only.
- Disconnect, reconnect, actor unload/reload, database restart, and rematch tests preserve exploration knowledge without disclosure.
- Existing perfect-information protocol compatibility follows an explicit version/migration policy rather than silently changing message meaning.
