# Task 12.01.06: Validate compatibility, privacy, and playability

Prove fog of war is understandable, non-leaking, performant, and optional before enabling it in authored play.

## Status

- [ ] Not started

## Dependencies

- 12.01.01-12.01.05, 10.01-10.04, 11.01.

## Scope

- Author at least one fog-enabled scenario variant using radius 3 as the initial baseline; retain the original perfect-information scenarios unchanged.
- Add deterministic visibility tables, property tests, golden fog replays, save/protocol migration fixtures, two-seat wire captures, hot-seat handoff tests, and headless Bevy disclosure assertions.
- Scan serialized projections, logs, UI text, ECS components, transition queues, exports, and error responses for seeded hidden sentinels.
- Benchmark visibility masks and both seat projections in opening/dense/endgame states on the 24x24 map, including reconnect payload size and invalidated Bevy updates.
- Run paired human sessions for exploration clarity, accidental shoulder-surfing, useful radius, hidden-blocker inference, check comprehension, settlement comprehension, match duration, and stalemate/frustration risk.
- Amend the GDD, player guide, privacy statement, protocol/save compatibility notes, help legend, and operator guidance only when the feature is actually shipped.

## Acceptance criteria

- Automated disclosure tests fail when any seeded hidden fact appears in a forbidden surface.
- Fog-enabled replays and reconnects reproduce both players' exploration masks and projection hashes at every revision.
- Existing perfect-information golden fixtures and UX remain unchanged.
- Radius 3 is retained or changed only with recorded playtest evidence, and the final scenario value is documented as tuning rather than a global rule.
- Players can explain undiscovered/explored/visible states, why an enemy disappeared, which match facts remain public, and when full replay truth becomes available.
- 24x24 fog computation, payload sizes, and rendering remain within recorded release-profile budgets.

## Cross-cutting concerns

- Adversarial privacy testing, accessibility, backward compatibility, representative performance evidence, balanced paired playtests, and documentation consistency.
