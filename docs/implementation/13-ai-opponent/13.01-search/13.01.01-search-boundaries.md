# Task 13.01.01: Define search boundaries and turn semantics

Create the engine-facing abstractions and action model needed by minimax without embedding policy in rules or UI code.

## Status

- [x] Done

## Implementation notes

- Added the standalone `crownline_ai` workspace crate with a one-way dependency on `crownline_core`; it has no Bevy, network, persistence, or filesystem dependency and core remains unaware of AI policy.
- Defined replaceable `SearchPolicy`, `Evaluator`, `MoveOrderer`, `Cancellation`, immutable `SearchRequest`, bounded `SearchLimits`, structured evaluation/result diagnostics, deterministic cancellation token, and typed rules/evaluation/limit errors.
- Added stable typed `ActionKey` ordering and `legal_search_actions`, which expands reducer-produced Move and legal Hold actions in command phase and only `legal_mandatory_choice_actions` for the first frozen promotion or produced-Pawn choice. Draw/resign control actions are not search plies.
- Maximizing/minimizing ownership is derived from canonical `active_player`, never ply parity. Mate-distance wins/losses, draw zero, heuristic bounds, node/depth/quiescence/deadline limits, and explicit stop reasons are pinned at the crate boundary.
- Table tests cover repeatable command ordering, legal Hold, locked promotion kinds, exact Pawn-placement coordinates, unchanged maximizing ownership through choices, terminal action emptiness, and mate-distance scoring.

## Dependencies

- 02.02.02, 03.01.02, 04.03.01-04.03.03, 04.04.02, 04.05.02.

## Scope

- Add a dedicated AI module/crate that depends on `crownline_core`; core must not depend on it.
- Define replaceable `SearchPolicy`, `Evaluator`, `MoveOrderer`, and `SearchLimits` boundaries plus structured result/diagnostic types.
- Enumerate legal reducer actions for command and mandatory-choice phases, including Move, Hold, promotion kind, and produced-Pawn placement. Mandatory choices consume `legal_mandatory_choice_actions`, including frozen promotion eligibility, instead of synthesizing all four promotion kinds.
- Model a search ply as one reducer action while selecting maximizing/minimizing behavior from `active_player`, not ply parity.
- Define mate-distance terminal scores, draw scores, score bounds, stable action ordering, cancellation, and node/depth/deadline stop reasons.

## Acceptance criteria

- Every non-terminal phase with a legal action produces a stable non-empty action list; terminal state produces none.
- Search never expands a promotion kind omitted by the queued control snapshot.
- Promotion and Pawn placement keep the same maximizing side until the reducer advances the active player.
- Interfaces permit alternative evaluators/orderers/search policies without exposing Bevy, networking, filesystem, or wall-clock APIs to core.
- Table tests cover command, Hold, both mandatory choices, terminal states, and stable ordering across repeated runs.

## Cross-cutting concerns

- Ownership boundaries, exhaustive typed actions, deterministic ordering, no cloned-state mutation leaks, and explicit numeric score limits.
