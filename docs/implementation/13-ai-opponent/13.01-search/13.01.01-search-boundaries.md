# Task 13.01.01: Define search boundaries and turn semantics

Create the engine-facing abstractions and action model needed by minimax without embedding policy in rules or UI code.

## Status

- [ ] Not started

## Dependencies

- 02.02.02, 03.01.02, 04.03.01-04.03.03, 04.04.02.

## Scope

- Add a dedicated AI module/crate that depends on `crownline_core`; core must not depend on it.
- Define replaceable `SearchPolicy`, `Evaluator`, `MoveOrderer`, and `SearchLimits` boundaries plus structured result/diagnostic types.
- Enumerate legal reducer actions for command and mandatory-choice phases, including Move, Hold, promotion kind, and produced-Pawn placement.
- Model a search ply as one reducer action while selecting maximizing/minimizing behavior from `active_player`, not ply parity.
- Define mate-distance terminal scores, draw scores, score bounds, stable action ordering, cancellation, and node/depth/deadline stop reasons.

## Acceptance criteria

- Every non-terminal phase with a legal action produces a stable non-empty action list; terminal state produces none.
- Promotion and Pawn placement keep the same maximizing side until the reducer advances the active player.
- Interfaces permit alternative evaluators/orderers/search policies without exposing Bevy, networking, filesystem, or wall-clock APIs to core.
- Table tests cover command, Hold, both mandatory choices, terminal states, and stable ordering across repeated runs.

## Cross-cutting concerns

- Ownership boundaries, exhaustive typed actions, deterministic ordering, no cloned-state mutation leaks, and explicit numeric score limits.
