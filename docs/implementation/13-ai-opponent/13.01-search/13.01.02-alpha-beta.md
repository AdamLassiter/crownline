# Task 13.01.02: Implement iterative alpha-beta search

Choose legal actions with deterministic depth-first minimax, alpha-beta pruning, and iterative deepening.

## Status

- [ ] Not started

## Dependencies

## Scope

- Implement fail-soft alpha-beta over reducer-produced successor states with exact terminal scores and evaluator scores only at the search horizon.
- Complete depths from 1 upward, retaining the last fully completed result when cancelled or limited.
- Support explicit maximum depth, node budget, optional host deadline, and cancellation token; check bounds at deterministic node boundaries.
- Preserve a principal variation and structured counters without making diagnostics affect ordering or score.
- Use stable action identity as the final tie-break so identical state/configuration/node budget yields identical output.
- Defer transposition tables, aspiration windows, parallel search, opening books, and pondering behind the search boundary rather than partially implementing them.

## Acceptance criteria

- Tactical fixtures prove minimax choice, alpha/beta cutoffs, mate-distance preference, draw handling, and correct same-player mandatory-choice recursion.
- Node-limited searches are byte-for-byte deterministic and never exceed the documented bounded accounting allowance.
- Cancellation/deadline returns the last completed depth and never a partially explored root choice.
- Input state/hash is unchanged after success, cancellation, evaluator failure, or limit exhaustion.

## Cross-cutting concerns

- Bounded recursion, overflow-safe mate scores, reproducible diagnostics, cancellation latency, and representative debug/release benchmarks.
