# Task 13.02.01: Build the evaluation heuristic

Score non-terminal positions from explicit, independently testable Crownlines features.

## Status

- [x] Done

## Implementation notes

- Added the versioned, serializable `EvaluationWeights` baseline and replaceable `BaselineEvaluator`; changing weights or disabling a component does not alter search, canonical state, saves, or protocol schemas.
- Initial material values are Pawn 100, Knight 320, Bishop 330, Rook 500, and Queen 900. Kings have no capturable material value: terminal wins, losses, and draws override all heuristic features with exact search scores.
- Added named signed components for legal mobility, attacked/defended piece safety, check, Pawn advancement and connection, promotion-site distance/candidacy, the control-derived or frozen queued promotion tier, centre access, and terrain activity.
- Added realm components for settlement ownership, governors, founder safety, uninterrupted continuity, establishment and production progress, produced Pawns, and transfer pressure. Realm control and governance are consumed from canonical core queries rather than reimplemented.
- Every component uses deterministic integer arithmetic, is evaluated from the declared root perspective, and is bounded before the total is clamped below mate scores. The default non-material weights are intentionally provisional tuning data: mobility 2, safety 8, check 80, Pawn advancement 3/connection 6, promotion distance 4/candidate 20/tier 25, centre 2, terrain 5, ownership 90, governor 20, founder safety 15, continuity/development 12, production 10, produced Pawn 35, and transfer pressure 25.
- Tests cover zero-valued symmetric openings from either seat, exact material isolation, root-perspective sign symmetry, terminal override, configuration-version rejection, named component totals, and extreme-weight score bounds.

## Scope

- Start with configurable signed material values for Queen, Rook, Bishop, Knight, and Pawn; Kings use terminal/royal-safety logic rather than a capturable material value.
- Add bounded components for legal mobility, attacked/defended pieces, King exposure/check, Pawn advancement/structure, promotion distance/candidacy, currently unlocked promotion tier, centre/crossing access, and terrain-constrained activity.
- Add realm components for settlement ownership, founder safety, governor count/quality, continuity, establishment/production progress, readiness, supported Pawn, and vulnerability to interruption or transfer.
- Evaluate from a declared root-player perspective and keep every component symmetric under player/board rotation.
- Return a score breakdown with named integer components; weights are versioned data and use saturating/bounded arithmetic below mate-score ranges.

## Acceptance criteria

- Exact fixtures isolate every component and prove the expected sign, bounded magnitude, and rotational/player symmetry.
- Terminal outcome always overrides heuristic material/realm advantages.
- Removing a governor, exposing a King, nearing promotion, and completing settlement progress change only the documented components.
- Promotion potential reads `realm_control_score` and queued `PromotionEligibility`; it must not assume a candidate can become a Queen or count the same realm value again under an undocumented component.
- Default weights are documented as an initial baseline and can change without altering search code or save/protocol schemas.

## Cross-cutting concerns

- Explainability, integer determinism, feature independence, score overflow safety, and tuning provenance.
