# Task 13.02.02: Define and calibrate difficulty profiles

Provide several predictable strengths using search effort and heuristic breadth rather than illegal knowledge or arbitrary move randomization.

## Status

- [ ] Not started

## Dependencies

- 13.02.01, 10.03.00, 10.04.01.

## Scope

- Define named profiles such as Apprentice, Steward, and Warden with explicit maximum depth, node budget, quiescence limits, enabled evaluation components, and optional move-time cap.
- Keep stable tie-breaking at every level; easy play comes from shallow/narrow reasoning, not seeded blunders or selecting a known-worse move after search.
- Establish scenario overrides for tutorial/challenge content without changing global profile meaning.
- Build a deterministic position corpus spanning openings, captures, check, terrain chokepoints, settlement claims/governance/production, promotion, sparse endgames, and all map sizes.
- Record decision quality, nodes, completed depth, elapsed release time, and regressions against a stronger reference profile; labels remain provisional until human evidence exists.

## Acceptance criteria

- Every profile has a versioned configuration and reproducible node-limited result corpus.
- Higher profiles use a monotonic superset of search/evaluation capability unless a documented tuning experiment says otherwise.
- Apprentice responds within the interactive budget on the 24x24 corpus; stronger profiles expose progress/cancellation and bounded maximum time.
- Difficulty names are not presented as validated player skill levels until paired human playtests support them.

## Cross-cutting concerns

- Honest UX, deterministic baselines, target-hardware performance, data-driven tuning, and no hidden bonuses or rule exceptions.
