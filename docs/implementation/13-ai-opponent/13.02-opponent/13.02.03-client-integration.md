# Task 13.02.03: Integrate asynchronous local AI play

Allow a local match to assign either seat to an AI profile while keeping UI, clocks, saves, and lifecycle authoritative.

## Status

- [x] Done

## Implementation notes

- Added Human or Apprentice/Steward/Warden AI controllers independently for North and South in local setup. F7/F8 cycle seat controllers, X swaps names and controllers together, and two Humans remains the compatibility default.
- Added an off-update-thread search worker using immutable scenario/state snapshots and a single-slot bounded result channel. Snapshot identity includes cancellation epoch, session, scenario, revision, active player, and repetition-position identity.
- Results mutate play only after matching the still-active uncancelled job and current snapshot. Pause, load, rematch, setup changes, terminal transitions, superseding positions, and application shutdown cancel work; stale or canceled results are reaped and discarded.
- AI command moves and mandatory promotion/Pawn-placement choices submit exactly one action through `apply_timed_action` and the existing local transition queue. Human board and lifecycle commands are suppressed during an AI-controlled turn.
- Normal configured local clocks continue advancing in `PreUpdate` while the worker thinks, so real think time is charged once; reducer submission uses zero additional elapsed time. Node-only developer tests explicitly disable the profile deadline and therefore use zero synthetic clock time.
- The existing bottom interaction/status surface reports profile and bounded depth/node effort while thinking, then completed depth, elapsed time, and ordinary/tactical node counts without naming the chosen move. Search failure offers explicit R retry or F forfeit and never manufactures an action.
- AI seats are currently rejected for fog scenarios rather than granting hidden canonical knowledge. A future imperfect-information policy can replace this honest boundary without weakening fog disclosure.
- Tests cover controller cycling/defaults, legacy and AI save round-trips, exact single reducer submission, cancellation and stale epoch/revision rejection, asynchronous mandatory choices, and an AI terminal smoke fixture. The normal rendering/reduced-motion path remains unchanged because AI transitions use the same queue as humans.

## Scope

- Extend local setup with Human/AI seat type and AI profile selection; default remains two humans and existing saves remain compatible.
- Run search off the Bevy update thread against an immutable scenario/state/revision snapshot and return a typed action/result through a bounded channel.
- Cancel on pause, load, rematch, scenario/seat change, terminal state, application exit, or superseding revision; discard every stale result before reducer submission.
- Resolve AI mandatory choices through the same asynchronous decision path and submit exactly one reducer action at a time.
- Decide and document clock policy: configured AI think time is charged, pause remains host-controlled, and node-only developer runs use explicit synthetic timing rather than silently stopping clocks.
- Show thinking profile, completed depth, bounded progress, cancellation/error fallback, and last decision summary without exposing a best-move hint during the human turn.

## Acceptance criteria

- Human-vs-AI works with AI on North or South; developer AI-vs-AI can complete deterministic smoke matches.
- Frames and input stay responsive while searching, and only a matching scenario/revision/active-player result can mutate state.
- Save/load, pause, resignation, timeout, rematch, reduced motion, and mandatory choices cancel or resume safely without duplicate actions.
- Search failure produces an actionable retry/forfeit choice and never invents an illegal fallback action.

## Cross-cutting concerns

- Thread lifecycle, bounded channels, stale-result safety, clock fairness, accessibility, structured diagnostics, and clean shutdown.
