# Task 14.01.02: Present objectives, hints, and progress

Provide accessible guidance and progression without covering the board or recommending moves before the player asks.

## Status

- [ ] Not started

## Dependencies

- 14.01.01, 06.03.01, 07.02, 07.03.03, Bug 017.

## Scope

- Add a guided-play setup/category browser and a bounded objective surface using the existing screen-region contract.
- Show current lesson purpose, observable objective, completed stages, failure/retry state, and optional escalating hints keyed from authored data.
- Trigger explanations from typed accepted transitions and predicate changes; never expose hidden reducer internals or AI principal variations.
- Make hints player-requested after the initial instruction, with reveal count recorded for local completion evidence but no telemetry.
- Persist scenario/stage/completion/best bounded metrics separately from canonical save data; support reset and replay without deleting ordinary saves.

## Acceptance criteria

- Keyboard-only and pointer users can select, start, inspect hints, retry, resume, and leave guided content.
- Text remains readable at supported scales and never overlaps board, Match, Settlements, help, or mandatory-choice UI.
- Save/resume reconstructs the same canonical state and lesson stage; reset is explicit and recoverable until confirmed.
- No hint or completion surface appears in ordinary competitive matches.

## Cross-cutting concerns

- Accessibility, localization keys, bounded local progress, no telemetry, UI ownership, and canonical/presentation separation.
