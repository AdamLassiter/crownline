# Task 14.01.02: Present objectives, hints, and progress

Provide accessible guidance and progression without covering the board or recommending moves before the player asks.

## Status

- [x] Done

## Implementation notes

- Added a guided browser reached from local setup by pointer or `G`, with bounded scrollable copy, category/kind/progress summaries, previous/next selection, start, exact resume, two-step reset confirmation, and back controls. Guided content remains absent from ordinary online and competitive match surfaces.
- Added an objective surface as a child of the existing Match panel body, so it inherits the established side-region ownership, scrolling, UI scaling, collapse behavior, and pointer capture instead of overlaying the board, Settlements, help, interaction log, or mandatory-choice controls.
- Stage copy resolves localization keys through the bundled `en-US` guidance catalog; missing entries are explicit authoring diagnostics. The visible objective is rendered as player-facing canonical facts/events rather than reducer internals, AI scores, or principal variations.
- Accepted local reducer transitions are mirrored to independent playtest and guided consumers. Typed events and read-only predicates advance or fail stages; rejected actions never mutate guidance counters. Hints are only revealed by pointer or `J`, while retry (`T`), replay, and leave (`Esc`) remain available without reusing the gameplay Hold key.
- Added bounded, versioned `guided-progress.json` storage separate from the three ordinary save slots. It atomically stores completion, attempts, retries, hint counts, whole-attempt best action/turn metrics, and one exact canonical resume/stage-start snapshot; guided play disables ordinary F5/F9 mutation and reset never touches normal saves.
- Resume validation checks the embedded scenario and schema, stable guided/stage references, hint bounds, canonical current and retry-state hashes/invariants, and content drift before restoring. Tests cover exact canonical round-trip, malformed progress, bounded entries, two-step reset, independent transition consumers, pointer controls, owned panel layout, and absence of competitive objective copy.
- A live X11 startup smoke remained healthy for the full eight-second probe; the command was terminated by the expected timeout with no Bevy startup or ECS errors.

## Scope

- Add a guided-play setup/category browser and a bounded objective surface using the existing screen-region contract.
- Show current lesson purpose, observable objective, completed stages, failure/retry state, and optional escalating hints keyed from authored data.
- Trigger explanations from typed accepted transitions and predicate changes; never expose hidden reducer internals or AI principal variations.
- Make hints player-requested after the initial instruction, with reveal count recorded for local completion evidence but no telemetry.
- Persist scenario/stage/completion/best bounded metrics separately from canonical save data; support reset and replay without deleting ordinary saves.

## Acceptance criteria

- Keyboard-only and pointer users can select, start, inspect hints, retry, resume, and leave guided content.
- Text remains readable at supported scales and never overlaps board, Match, Settlements, help, or mandatory-choice UI.
- Save/resume reconstructs the same canonical state and lesson stage; reset is explicit and recoverable until confirmed.
- No hint or completion surface appears in ordinary competitive matches.

## Cross-cutting concerns

- Accessibility, localization keys, bounded local progress, no telemetry, UI ownership, and canonical/presentation separation.
