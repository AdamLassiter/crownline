# Task 14.01.03: Connect scenario-controlled AI opponents

Let guided content select constrained AI behavior while preserving the general AI interfaces and canonical rules.

## Status

- [x] Done

## Implementation notes

- Added stable `apprentice`, `steward`, and `warden` profile IDs plus a closed registered-policy resolver. Guided content can select bounded material, terrain, or realm feature subsets, or the deterministic `teaching_first_legal` response policy; unknown IDs and arbitrary embedded weights fail before the match starts.
- Guided setup assigns only the authored opponent seat to the existing local AI controller and preserves the declared human seat. General profiles, registered teaching policies, and exact replies all run through the same immutable snapshot, bounded worker channel, cancellation epoch, stale-result checks, reducer submission, clock charging, mandatory-choice handling, and retry/forfeit failure boundary as ordinary local AI.
- Reply-tree nodes now carry the exact canonical AI-to-act state, its repetition identity, one typed action, and bounded child references. Scenario validation rejects wrong seats, drifted/duplicate positions, illegal actions, unknown/duplicate/self children, cycles, unreachable nodes, and a root that disagrees with an AI-to-act guided start.
- At runtime an exact challenge reply is selected only by the current canonical repetition identity. An undeclared position stops safely with a content-drift message instead of falling back to heuristic play; the final action is still revalidated by the reducer before it can mutate the match.
- Authored AI action bounds are counted from accepted typed transitions and stop further replies until retry/leave. Failed or completed guidance also suppresses further AI work, while guided retry is ordered before AI scheduling and cancels any prior worker generation.
- Player-facing challenge status reports only that a bounded registered reply is thinking/completed. Search profile, depth, nodes, timing, and stop reason remain available in structured debug diagnostics without exposing score, chosen move, or principal variation.
- Tests cover closed profile/policy registries, bounded feature policies, deterministic first-legal selection, exact reply lookup, canonical node legality/drift validation, and reuse of the existing exact-one-action/stale/cancellation worker path.

## Scope

- Resolve authored AI profile/seat/limits through the same validated difficulty registry used by ordinary Human-vs-AI play.
- Allow a lesson to select an evaluator feature subset or bounded response policy by registered ID, never embedded code or an arbitrary weight payload.
- Support deterministic authored reply sets/solution-tree replies for exact demonstrations and general alpha-beta replies for open practice.
- Validate that every authored reply is legal at its node and define deterministic fallback/error behavior if content and canonical rules drift.
- Suppress AI score/principal-variation display during challenges while retaining structured developer diagnostics.

## Acceptance criteria

- Tutorials can use a predictable teaching reply policy; open practice can use a named general difficulty.
- Challenge correctness never depends solely on a heuristic AI choosing the expected defense when other legal defenses refute the solution.
- Content version/rules drift fails validation before play rather than producing an illegal or misleading opponent move.
- AI cancellation, clocks, mandatory choices, retry, and stale-result protections remain identical to ordinary local AI play.

## Cross-cutting concerns

- Registered behavior only, deterministic replies, honest challenge validation, no executable scenario content, and reusable AI/client boundaries.
