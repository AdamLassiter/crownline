# Task 14.02.05: Validate progression and difficulty

Verify that tutorials teach their objectives and challenges become harder for defensible reasons.

## Status

- [ ] Not started

## Dependencies

- 14.02.01-14.02.04, 10.03.00-10.03.02, 10.04.01.

## Scope

- Archive deterministic construction, objective, solution-tree, replay, save/resume, and AI-response evidence for every guided scenario.
- Measure branching factor, shortest/alternative solution length, required quiet moves, Warden search depth/nodes, and tactical/realm feature coverage.
- Run representative new-player sessions for comprehension and experienced-player sessions for challenge, recording completion, retries, hints, time, misconceptions, and accessibility issues locally.
- Reorder, revise, or relabel content from evidence; do not equate board size, AI profile, or engine node count alone with human difficulty.
- Update the GDD, player guide, help, release boundaries, compatibility notes, and packaging inventory only when the epics actually ship.

## Acceptance criteria

- Tutorial participants can explain and later apply each target mechanic without the demonstration prompt.
- Difficulty bands show increasing human completion cost and at least one corroborating solver metric, with documented exceptions.
- All content works at supported UI scales, keyboard-only, reduced motion, and both board orientations.
- Existing competitive scenarios, golden replays, local setup defaults, and online play remain unchanged.
- Performance stays within interactive client/search budgets on representative target hardware.

## Cross-cutting concerns

- Human evidence over engine proxies, consented non-identifying records, accessibility, regression isolation, documentation truth, and reproducible solver/build metadata.
