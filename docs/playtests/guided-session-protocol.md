# Guided scenario human-session protocol

Use an exact packaged build and record its revision. Obtain consent to retain a
non-identifying observation record; use participant labels only. Never record
names, contact details, room codes, credentials, or telemetry.

## New-player session

Run the movement, realm, and Royal tutorial sequence. After each demonstration,
start the related assessment without showing the earlier prompt and ask the
participant to explain the governing rule before acting. Record scenario ID,
completion, elapsed time, retries, hints revealed, explanation accuracy,
misconceptions, keyboard/pointer method, UI scale, board orientation, and
reduced-motion setting.

## Experienced-player session

Run the six exact challenges in their displayed order and the Warden challenge
last. Record the same fields plus first attempted action, alternative solution
found, perceived difficulty rank, and whether difficulty came from tactics,
realm planning, interface discovery, or wording.

At least one session in each group must be keyboard-only. Across the retained
set, cover both board orientations, reduced motion on and off, and the minimum,
default, and maximum supported UI scales. Stop and record an accessibility issue
if text, focus, mandatory choices, hints, retry, or leave controls cannot be
used without pointer input or color distinction.

## Review rule

Aggregate records before changing content. Difficulty bands require increasing
human completion cost plus at least one corroborating solver metric; document
exceptions. A failed explanation or repeated misconception is a content defect,
not participant error. Preserve pre-change records and regenerate scenario and
solution hashes after every content revision.
